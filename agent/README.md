# 小满运行与接口

来源：用户提供的 Muse `jixu-agent-0.1.0.zip`（SHA256 `71561ea798de9f917390a76b05be120bcd615bc2313e9d234cc40ed2445e3b95`）。原包沙箱记录不代表当前环境验收。

Node 22 运行，业务只调用正式 Flow HTTP API。模型将自然语言解析成受校验的任务意图，或提供极序相关的无工具交流；库存、价格、账款来自后端。写入必须通过预览卡人工确认。已冻结的业务编排由 `src/runtime.js` 统一分发，正式后端与本地独立服务共享运行入口。

## 运行

正式入口是原后端 `/api/assistant`，与当前 ERP API 同源、同认证及凭据续期。后端通过当前 `authMiddleware` 和仪表盘/报表任一入口权限后，才解析最多 32KiB JSON；继续沿用全局 CORS、限流、并发与停机守卫。健康也需认证。正文不能提供身份、权限或仓库范围，内部 API 客户端仅使用本机实际监听端口与当前访问令牌，不接受请求 Host 或外部 Flow 地址。每个业务入口仍保留原权限、确认、原请求键与回查核验。

镜像把包声明与运行源码复制到 `/opt/flowcube-agent`，原后端进程按固定可信路径懒加载；不增加微服务、监听端口或镜像。Compose 仅向后端注入 `AGENT_MODEL_*`，任务保存在 `assistant_data` named volume 对应的 `/var/lib/flowcube/assistant`，目录权限 0700、任务文件 0600。当前由单个后端进程持有运行实例和任务锁；同一 JSON 文件不提供多进程共同写入协议。模块导入与迁移命令不会启动监听或加载任务。

可选本地独立服务仍使用原入口：

```sh
FLOW_BASE_URL=http://127.0.0.1:3893 AGENT_DATA_DIR=/absolute/private/agent-tasks AGENT_ALLOWED_ORIGINS=http://127.0.0.1:5198 npm run dev:agent
```

`AGENT_MODEL_BASE_URL`、`AGENT_MODEL_NAME`、`AGENT_MODEL_API_KEY` 通过进程环境注入。服务不自动读取或写入密钥文件；示例只说明变量名，不包含凭据。任务文件含业务预览，须放在仓库外私有目录。服务仅监听 `127.0.0.1:8932`，Origin 必须精确匹配允许列表。

前端使用 `/api/assistant`，不依赖独立 8932 服务、Vite 专用代理或开关。独立服务仅供本地调试，保留其回环监听和精确 Origin allowlist。

## 接口与边界

以下相对路径在正式后端均加 `/api/assistant` 前缀，并使用 `{success:true,message,data}` 成功信封，失败沿 `AppError` 统一信封。独立服务保留原无前缀、无外层成功信封的本地接口；独立健康探针只返回配置状态。

- `GET /health`：正式入口需认证；仅返回配置状态，`planner=llm` 不代表实际模型调用已验证。
- `GET /me`、`GET /tools`：正式入口由原后端认证核对当前身份，独立服务每次向 Flow 核对。
- `POST /chat {message, taskId?, choiceId?}`：查询、极序交流或生成待确认任务，不接受文字代替确认。`taskId` 是当前选中记录；原候选选择和明确改数量沿该任务继续，完整的新问题和问候另建任务，服务端负责区分。`choiceId` 必须属于原候选集合，并重查原搜索；不可用任意 ID 绕过搜索。
- `GET /tasks`：最多 30 条当前用户仍可访问的任务，最近更新在前；`GET /tasks/:id` 返回单条同形状安全视图。字段为 `id/graph/state/userText/reply/preview/result/error/candidates/queryOutcome/revision/confirmationBlocked/createdAt/updatedAt`。不返回原请求键、内部载荷、私有库存字段、角色权限或凭据；撤查看权、撤仓后隐藏原快照，预览超过有效期显示 `EXPIRED`。
- `POST /tasks/:id/confirm {revision?}`：仍兼容不传版本的原调用；前端始终携带版本，旧版返回 `409 PREVIEW_REVISION_CONFLICT`，被暂停的版本返回 `409 PREVIEW_CONFIRMATION_BLOCKED`。选择、改量、放弃、确认、恢复共用任务锁。执行中的任务按原键及领域 action 查回执恢复，不重发写请求；已完成任务返回原结果，原收款任务恢复原第二段核销卡。
- `POST /tasks/:id/cancel {}`：仅取消当前尚未执行且未过期的业务预览，复核属主及当前查看、仓库与相应办理权限；合法状态按状态机进入 `CANCELLED`，重复取消幂等。`CONFIRMED/EXECUTING/RESULT_UNKNOWN/VERIFYING/ESCALATED/DONE` 不允许取消，不隐藏原结果、不变更请求键或业务单。放弃 `D-settle` 只影响核销预览，已登记收款和第一段结果保留。
- `/chat`、`/confirm` 与 `/cancel` 响应为 `{reply, task:{id,graph,state,queryOutcome,revision,confirmationBlocked,userText}, preview?, result?, candidates?, diffs?, businessPages?}`。`businessPages` 仅含代码白名单业务页标识；前端用当前路由注册表与权限决定是否显示入口，模型文本中的 HTML、链接仍不作为入口渲染。待确认时优先返回持久化预览，首次即包含与原任务相同的 `builtAt/expiresAt`，版本与恢复结果一致。候选项至少 `id/title`，可含 `type/subtitle/details`；资金账户未选时 `preview.account=null`、`preview.accounts` 保留，账户序号回复继续可用。

例如先发送 `{ "message": "合成铰链库存" }` 得到候选，再发送 `{ "message": "选这个", "taskId": "原任务ID", "choiceId": 2 }`；待确认销售预览可发送 `{ "message": "改成3个吧", "taskId": "原任务ID" }` 或“多了，改5个”。单行可省略上下文，多行需唯一商品或明确行号；行号与商品冲突不猜。修订前持久化暂停确认，失败保持原正文、原预览和版本；负数、超两位有效小数、整数商品小数不取绝对值或舍入。只有澄清成功或明确“继续原版”且重新读取商品规则、客户价和库存成功，才产生新 `revision`、解除暂停并显示数量及合计的旧→新变化。执行中或结果未知时禁止改量和换键续写；“单价改3”仍属不支持的改价，文字“确认”只指引卡片按钮。

界面提供“放弃预览”；自然语言仅接受独立、明确的“放弃当前预览”“取消这份预览”等当前预览意图，不从取消订单、删草稿或混合命令中推导业务取消。改量或放弃响应丢失时，前端冻结旧确认并只 `GET /tasks/:id` 核对；读回同版待确认不能解除本地冻结，须明确重试修订/继续原版产生新版本或完成放弃。放弃恢复不能调用 `/confirm`。这些行为由 `preview-controls.test.js`、正式回环 `embedded-api.test.js` 和 `AgentWorkspace.test.tsx` 回归，不代表真实业务数据或浏览器验收。

前端在待确认消息或放弃请求发出前，按当前账号、服务器、任务与每次尝试的独立键保存冻结标记并读回验证；记录仅含版本与尝试身份，不保存 token、原文或业务明细。卸载、刷新、同账号重登和正常 token 续期不解除冻结，会话代次只用于拒绝迟到回调。新尝试读取本任务全部未决标记并取最高版本，独立键避免并发覆盖或清理误删另一尝试。请求发出前保存已观察尝试集合，响应只能清理该集合中版本合格的标记，不能清晚生尝试。普通 GET 的更高版本只更新展示，不能证明未知修改已经完成；只有同任务明确修订/选账户成功的新预览，或至少同版的服务端暂停/终态才可按原观察集合解冻。文字确认回显高版也不解除未知修改。成功但未修改的回复只能清除本轮新建标记。v1 共享旧键保留原字节，按账号、服务器、任务与完整旧标记身份另存已核记录，不覆写或删除可能被旧标签页并发更新的 v1 键。存储损坏、不可读写、静默拒写或清理读回失败均暂停待确认写入；发前持久化失败拒发修改/放弃。但服务端 `CONFIRMED/EXECUTING/VERIFYING/RESULT_UNKNOWN/ESCALATED` 的原任务恢复不依赖编辑存储，仍沿原 ID/请求键只查回执和原单。客户端确认未知而服务端仍待确认时，原确认版本不同/缺失或存储失败只 GET，不授权当前版本。跨实例与存储恢复回归见 `previewFreeze.test.ts`、`AgentWorkspace.test.tsx`，真实 Agent 五种恢复态的原键/零业务 POST 合同见 `conversation-recovery.test.js`。

中文数量和行号仅接受可精确核对的规范整数写法（如“三”“十”“十二”“二十”“一百零二”，以及单独“两”或百/千前的“两”）。“一二”“十十”“零三”“二百二”等连续、重复或省略写法不猜值，要求改用阿拉伯数字，保留原预览并暂停确认；此规则不扩展金额输入能力。

任务图：库存、销售草稿、销售占库、补货建议、采购草稿、往来台账、两段收款核销、卡点、经营简报。正式全局搜索另需仪表盘权限，建单后的核验另需单据查看权限，不代授权限。完整列表最多核对 2000 条，超限/重复/总数变化停步；退货任务完整汇总暂不支持，按不可用呈现。

库存查询保留指定仓库并先验范围，不能把“二仓”扩成全授权仓。销售预览逐行读当前商品数量策略，整数商品 `0.5` 在出预览前拒绝，确认时再次核对。台账按客户 ID 的事件归属、未结列表按来源订单关联，手工与历史未关联账款不按同名绑定；`unassignedCount` 是应收侧全局未归属事件数，不能认定属于当前客户，也不能凭关联列表为空或余额零宣称全部结清。卡点和简报列出接口返回的可见单号、库存和异常事实，不编卡住原因。

补货主建议接口读取失败（包括 403/503）必须失败，不能冒充成功空集合或生成采购确认卡；成功的空集合仍可报告没有建议。经营简报对全部并行请求立即接住拒绝，每段独立保留成功数据或真实失败提示，不能因后段先失败而终止服务。

到账金额统一由 `src/receipt-amount.js` 从原文核对，规则、模型意图及规则回退共用边界。带货币标记/单位的到账前金额与到账后金额都核对，`5元到账` 与 `到账5元` 都是 5 元，客户编码数字不据此当成金额。保留负号与前导小数，`.5元` 为 0.50 元；非正金额、超出分位、多个金额及不能可靠识别的中文金额/倍率等表达要求重述，不会舍入、丢符号或变成未结全额。只有确实没写金额、且模型未提供有争议的金额时，才按关联未结全额试算；模型提供金额但原文缺少证明或不一致时停步。选账户和确认时也用相同解析复核原文、整数分值与登记载荷，旧版错误快照不能直接沿用。

## 人格与极序交流

人格集中在 `src/persona.js`，通过实际消息入口生效，用户可见名称只有“小满”。“在吗 / 叫什么名字 / 谢谢 / 你没听懂”等小轮次仅简短回应；只交流极序相关内容。极序业务概念、使用流程、排错思路和页面设计建议可进入 `G-chat` 无工具交流，复用现有模型环境配置；阅读习惯、天气、苹果公司等无关话题直接简短说明范围，零模型、零 Flow 调用，不创建普通闲聊任务。未配置或调用失败如实提示，不把失败当作完成。

`src/routing.js` 集中定义入口分类与规则任务图，避免入口白名单漏掉后续已支持的“欠款”等问法。实际单据、账款、库存查询以及正式编号优先进入业务；“这张单 / 那笔款 / 刚才那个”等缺少明确身份时先澄清，不交讨论模型猜对象。只有明确以极序页面/功能/流程为对象的话题或独立核心业务概念解释才进入无工具交流，未知话题默认不进入模型；仅添加“在极序里”前缀、明确把极序放一边，均不能放行其他对象的设计或生活话题。问句里包含“设计 / 讨论”不能覆盖真实业务查询意图。

“给甲公司开个单，上翻支撑2个”“给甲公司下单，上翻支撑2个”与“甲公司还欠我们多少钱”优先按确定性槽位进入原销售草稿或应收台账图，模型未配置、异常或无法识别不会把这些完整请求挡回能力清单。销售缺客户、商品或数量，以及欠款缺客户时先说明缺项；其余明确业务才可交受限意图解析器，模型结果仍经 `validateIntent` 校验。无法识别时明确未执行并请补充对象；删除草稿、改价、付款、审批、发货等图外动作明确不能代办，可显示当前有权访问的原业务页入口。原图权限、实体候选、当前工具事实和显式确认均保留。

开单逐条核对明细的商品与数量；首行、中间行或末行缺数量均在模型和实体搜索之前澄清，不允许模型补造数量。明细若只有数量（含多位数字、中文数量或数字间空白）也先澄清，不能把“12个”拆成商品“1”与数量“2”，也不允许模型补造缺失商品。明确图外动作按谓词识别，“把状态为草稿的订单发货／作废／审批”等不能借“状态／进度”或产品排错背景绕过拦截；夹带数量修改时原预览、版本与请求键仍保持不变。“待发货状态／待审批进度”等只读问题与极序概念解释继续按原边界处理；“极序里销售单作废后怎么恢复”等流程条件提问不按执行命令拦截，明确“先／帮我把订单发货，然后告诉我状态”仍拒绝代办。

带“顺便 / 然后 / 再给”等独立请求边界或分号的多意图消息只处理首件，第二件及后续事项明确标为尚未处理、请另发；整句与分句的绕规则、图外操作拦截先于拆分和任务续聊。同一开单中的逗号商品明细仍归为一件事。后续事项不进入首件的模型输入、客户或商品搜索，也不串联多个写任务；首件失败时保留失败原因，不能宣称查询或开单成功。

明确“换个话题”等切换时，用最后提出的新目标重新判断归属，前半句的极序页面或身份提问不能替范围外的新目标放行。真正换到极序审批概念或出库流程仍可说明；讨论模型及后续上下文只收到切换后的相关目标，不携带已放下的外部话题。整句中的绕规则请求仍优先拒绝。

交流模型只接收固定人格、已核对的当前能力边界、当前文本和本人最近最多 6 轮成功的极序讨论文本；历史最多 6000 字、每条最多 1000 字，当前文本最多 2000 字。业务任务原文、工具结果、Flow token、权限与请求键不进入交流消息，不挂工具、不调 Flow。设计仅是建议；未核实能力、配置、版本及实时数字不能补成系统事实。业务图外取消、付款、发货、改价及绕规则请求确定性拒绝或指路，原有业务能力、两段确认、原键恢复和执行后核验边界保持。

预占、现存与可用量的常见概念由本地稳定解释提供，依据当前 `inventory.service.js`、库存不变量和业务语义：预占不扣实存在库、不等于发货；列表可用、含预计可承诺和当前可拣分开说明。审批也由本地解释区分有权人员的业务审批与预览确认；普通收款确认后经正式校验入账，核销另确认，跨期等按原审批，具体配置仍以原系统为准。输出守卫先规范化 Markdown、货币和常见文字格式，再区分否定解释、状态标签与明确假设示例，仍拒绝第三人称或自称执行完成、未限定的业务数字、示例中夹带的实际数据及未核实配置。“多少度”等明显气温问题直接说明范围；真正请求审批仍拒绝。

新 `G-chat` 记录保存内部 `discussionScope=flow-product-v1`，名字问候可正常保留。没有该标记的旧闲聊，以及虽有标记但不符合当前极序主题范围的记录，都不出现在 `GET /tasks`、不提供详情恢复，也不进入新交流上下文；不删除原持久化数据。业务任务和待确认预览仍沿原授权完整保留。

已有历史文件若损坏、不是数组、任务编号重复或记录不完整，停止加载并保留原文件，正式接口返回脱敏 `503 ASSISTANT_HISTORY_UNAVAILABLE`，请管理员核对修复；不会默默清空历史或覆盖原请求键。缺少 `updatedAt` 的旧有效记录继续兼容。

到账原文同时保留客户片段、客户编码、完整单号和已识别日期；“甲公司付了25元，把SL20261026009那笔核销掉”识别为 2500 分及指定单号，不能把单号当第二笔金额，也不能删掉目标后按全客户账龄分配。本批不支持指定单据或日期的收款核销：在实体搜索和预览之前明确停步，显示已识别目标并引导原收付款页核对；缺少明确身份的“那笔”等目标同样澄清停步。常见单据前缀或明确单号语境才作为目标证据，AB123五金等混合客户名称与 C/KH 客户编码保留原字，不凭字母数字形状猜单据。

普通“甲公司付了25元核销”按原文客户与金额试算，付款主体中的“张钱”“给力五金”“帮忙商贸”等保留原名，不吞首词或尾字。仅无到账/付款谓词的旧“给甲公司核销”命令核对完整原片段与去命令前缀两种当前客户候选；命中不同客户时停步消歧，同一客户或只有命令解读有候选时沿原候选协议继续，第二段继承第一段已保存的客户选择，并仍须重新搜索核对；原候选撤销则停止核销，保留已登记款。不直接缩短名称后采用另一个客户；未找到原客户时引导按“客户名 到账 金额 核销”重述。模型改写的客户不替代原客户；模型补出的单号、日期或无法由原文证明的金额不能进入预览。客户主体沿金额解析实际采用的付款谓词定位，“甲收款五金到账25元核销”“甲核销服务到账25元核销”保留完整客户名，名称内的收款/核销字符不能截成另一客户。新入口和未执行的旧收款预览、选户与核销确认都复核目标/日期；选户及两段未执行确认另按当前权限重新搜索原文客户，核对原保存选择及预览客户 ID；旧意图中的缩名不作为证明。身份不一致、选择已不属于当前候选或读取失败均使预览失效，停止执行。第二段同样核对原文到账金额与预览整数分，不能沿用“原文5元、快照25元”的旧错误金额。若原收款已登记，只停止后续核销并提示处理原收款单，不能声称原登记被撤销。执行中或结果未知任务仍按原键回查，不换键重发。日期识别仅用于保留原文和安全停步，不新增业务日期、定向核销、跨期补录或财务权限能力。

单价和成本保留来源精度，十进制相乘后才对行额取分；实际收款遇历史非分账款先停下。采购批次部分成功时保留原任务，不重新建整批。

## UI 审计 T13：历史记录与原任务恢复（2026-10-28，本地实现）

历史标题从当前安全视图内的任务类型、客户/商品/单号等已有对象及收款阶段组成；缺少对象快照时保留原话作线索。第一段登记与第二段核销继续是两个独立任务、两个 ID、各自原请求键与两次确认。历史只按当前可访问记录中唯一的 `D-receipt.result.stage2TaskId` 关联 `D-settle`；若双方收款 ID 已知却不一致，则不组成展示组。不按同名、同金额或时间接近合并。首次确认向第二段交接时，前端只按原 confirm ID 与响应第二段 ID 补充相同展示关系；刷新后仍读服务端已有 `stage2TaskId`，没有新增持久关系协议。第一段完成记录可按该显式 ID GET 原核销任务，即使第二段已移出最近窗口，也不新建、不重登记；当前权限、属主、过期和资金阶段守卫仍由原入口核对。

首次加载普通待确认、消歧或已完成记录只提示待办，由用户手动恢复。`CONFIRMED/EXECUTING/RESULT_UNKNOWN/VERIFYING/ESCALATED`、待确认预览的本地冻结/存储错误和服务端暂停优先恢复，并一直保留明显的原任务提醒；新对话与手动选择不能抹掉本地确认未知的原结果查询入口。同账号、服务器与会话内，历史列表短暂读取失败保留最后已知任务与恢复 ID，并明确提示失败；401/403 收回旧快照。账号、服务器或会话代次变化仍销毁原组件并拒绝迟到响应。最近30条是有界窗口，原选中记录移出满窗口时只 GET 原 ID 复核；暂时失败保留最后已知恢复，原详情401/403/404才收回该快照。当前选中卡与已知待核集合分开：集合只保留各原 ID 的标题、状态、版本和本地未知/冻结协调信息，不缓存完整预览、账户、明细或执行载荷；切到新对话或其他记录、多项待核同时移出窗口，都保留各自入口。成功读取历史后对缺席的已知危险 ID 分别 GET 复核，临时失败保留，该原 ID 不低于已知版本的权威终态或401/403/404才收回对应入口。窗口外当前卡仍沿同一预览冻结刷新，存储失败仍禁确认。列表或窗口外原详情取得同 ID 不低于已知版本的权威终态时，解除该任务的本地确认未知提醒；其他 ID 或同 ID 非终态不能解除，也不清除其他预览冻结。危险原记录不可读时移除敏感快照，同时只保留“核对原业务结果、勿另发重复请求”的通用提醒；不能由不可读推断未执行或可重办。隐藏再激活的后台历史读取捕获选择代次；手选、新对话或新任务响应切换后，旧加载不能清除后来恢复的卡片，也不能用早读的低版本终态或同版非终态行覆盖较新详情/版本。历史与恢复集合使用同批有效行协调，两者都拒绝同 ID 的低版本终态，当前鉴权拒绝和有效版本终态仍独立处理。本地确认未知单独保留原确认版本，列表、详情与文字确认的非终态回复不能清除或改写该授权版本；只有有效终态或明确第一段完成交接才能解除。结果查询遇当前预览版本不同或原版本缺失时仅 GET 原任务，不授权确认后来版本，也不新增后端协议。

只有 `A-inventory` 和 `D-ledger` 在确定性实体搜索返回 `ENTITY_NOT_FOUND` 时持久化 `queryOutcome=not_found`，安全视图及紧缩响应仅对相应 `FAILED_FINAL` 只读记录透传，历史显示“未找到”。原任务状态、错误、确认与执行协议不变；权限、网络、历史无标记失败及全部写图失败仍显示未完成，不能从错误文本推断查询成功或已答复。

`AgentWorkspace.test.tsx` 与 `previewFreeze.test.ts` 覆盖手动恢复、全部危险执行状态、同归属历史失败、满30窗口外复核、换账号/服务器、迟到与并发加载、独立两段/明确关联及原核销过期恢复。原冻结、存储故障和确认原任务断言保留，原来依赖自动展开的夹具改为实际点击恢复。Agent 窄回归复用 conversation-recovery、receipt、preview-controls、embedded-api 与 task-store-integrity；两段关联断言核对独立原 ID/请求键、零重复登记与第二次确认仍必需。质量回归另复证真实 T03 修订可在异步价格读取期间跨过旧 TTL，安全视图先为 EXPIRED/revision1、完成修订后为 AWAITING/revision2；真实 confirmTask 拒绝旧版本且零写，而明确确认新版本才会写入新数量。前端实际查询按钮则证明原未知版本不同或缺失时没有发出该新版 POST。日志在任务外 `/tmp/flowcube-t13-*.log`。这些为合成组件/回环证据；GUI、真实业务与数据库、完整 Agent、lint、类型检查和构建由主任务分别验收，本实现者未执行。
