# 订单进度与操作记录

## 范围与页面

按用户确认的“作业进度／装箱进度”方向实现，16 类已保存单据统一提供操作记录；新建表单尚未取得单据 ID 时不显示历史页签。销售单保留原有订单信息、作业进度、取货明细和装箱进度，操作记录接入统一数据源。其他详情复用 `OrderDetailSections` 和 `DocumentActivityPanel`，长表横向滚动、完整展示，无分页。

| 单据 | 进度与明细 |
|---|---|
| 销售订单 | 原有作业、取货、装箱页保留；记录合并订单事件及关联仓库任务操作 |
| 采购订单 | 逐商品采购、已收、未收、超收和已上架数量，关联收货订单 |
| 收货订单 | 收货与上架数量、容器条码和当前库位、条码打印任务 |
| 采购退货 | 关联仓库任务状态、实际出库流水、扫码取货记录 |
| 销售退货 | 收货、质检合格、拒收、未检、上架数量，容器和条码打印 |
| 调拨订单 | 计划、已调出、在途、已调入数量及调出调入扫码记录 |
| 批次拣货 | 责任人、关联销售单、仓库任务执行、取货扫码、逐箱商品和箱贴打印 |
| 盘点单 | 账面、实盘、差异、录入状态及容器扫码记录 |
| 库存处置 | 逐商品计划处置量、执行状态、实际处置时间 |
| 采购申请 | 申请与转采购数量、各轮审批节点、处理意见 |
| 采购计划 | 逐行转采购状态、采购数量及关联采购单 |
| 退款单 | 实际已保存的确认与退款时间、当前状态 |
| 费用报销 | 实际提交、审批、付款节点和意见 |
| 超额放行申请 | 详情／记录弹窗、各轮审批节点和意见 |
| 改价申请 | 详情／记录弹窗、各轮审批节点和意见 |
| 物流运单 | 独立物流进度页显示已有轨迹，操作记录展示运单操作 |

批次原 `focus=print-closure` 快捷链接直接选中装箱／打印页，其他进度链接进入作业进度。保留“打开出库补打”入口。没有装箱业务的单据不套装箱流程。

## 数据与权限

本轮新增销售、采购、收货和调拨的共享履约面板：异常处理、交期、供货来源及采购影响见 `docs/order-fulfillment-2026-09-06.md`。原操作记录合并同事务保存的履约处理事件；原进度、取货、装箱和条码记录不替换。

- 新只读接口：`GET /api/document-activity/:type/:id`。类型白名单和正整数 ID 校验后，使用原模块查看权限，并先完成原详情的数据范围校验，再读取事件和进度。报销沿用本人／查看全部范围；采购计划没有当前用户可见明细时拒绝返回历史；物流沿用仓库范围。
- 当前工作区的进度和记录按 20 秒刷新，支持手动刷新、失败重试和取消请求。信息页切换时保持挂载，避免丢失尚未保存的输入；切换不同单据重置页签。页签支持方向键、Home、End。
- 进度使用原单据明细、关联仓库任务、扫码、容器、库存流水和审批节点。波次活动读取显式禁用原详情的进度回写，保持新接口只读。
- 数量差额按四位小数计算；不合计不同单位商品。采购未收数量只是实收差额，短装关闭的剩余量不解释为仍需收货。历史取消任务、取消包裹保留状态。
- 容器余量、库位是当前事实，可能已经受后续出库或调拨影响，不解释为首次收货快照。已有商品快照按原来源读取；没有身份快照的过程记录沿用商品主档关联。
- 条码／箱贴状态来自实际打印任务，支持无任务、排队、打印中、成功、失败、超时。保留补打历史；普通纸张打印发起不推断为物理打印成功。

## 操作记录的保存

迁移 `234_document_operation_events.sql` 新增独立订单操作摘要表，保存明确的单据类型、单据 ID、动作、原因、操作人、时间及原系统日志 ID。按完整请求路径归属，避免相邻 ID、不同类型串单；新建 ID 只取服务端成功响应，失败请求不进入成功操作记录。不得把请求正文、认证字段或付款字段复制进订单摘要。

现行 `opLogger` 在成功响应后异步保存摘要，与普通操作日志一样属于尽力记录；数据库写入失败会输出服务日志，不能承诺每个请求与订单状态在同一事务内落审计。已有业务事件继续作为业务过程的事实来源。独立摘要不随普通系统日志的例行清理删除。

展示合并已保存业务事件、仓库任务事件、审批动作、独立摘要和仍留存且能精确归属的旧请求日志。来源分开标明，不从原始请求体反推业务数量；未记录的操作人显示“未记录”。历史未留存或已清理的操作不能补造。该入口覆盖上述订单及申请，不改变财务凭证、发票、对账单等其他模块的原有审计设计。
