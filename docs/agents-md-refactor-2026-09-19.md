# AGENTS.md 文档体系重构（2026-09-19）

## 问题：规则写了，但进不了上下文

`AGENTS.md` 是工作区指令注入的载体，而注入有**字节预算**：默认 `standard` 预设 **64 KiB**，**超出即静默截断尾部**
（不报错、不告警）。重构前该文件 **130,634 字节**，于是：

- 默认预设下**只有前半部分进得了上下文**，最后一个完整章节停在 §7 —— **§8 财务/权限/时间、§9 前端与 PDA、
  §10 打印与部署运维、§11 索引全部不可见**；
- 本机之所以"看得见全文"，是因为 `standard-fullctx` 副本把预算提到 128 KiB（属**部署侧配置**，换机器即失效）；
- 更糟的是**没有任何信号**：规则照写、CI 照绿，但模型根本读不到 → 等于没写。2026-09-18 的同类事故已经证明过
  这个失效模式：文件 211 KB 时新会话注入的是一份**过时的 `CLAUDE.md`**，本文件显示 `omitted`，全链路不报错。

根因不是"文件太大"，而是**放错了内容**：把「每次都必须生效的约束」和「按需查阅的项目知识」混在一个会被截断的容器里，
结果约束被知识挤出去。

## 方案：按「载体分工」重构

1. **规则的首选载体是 `tests/` 守卫，不是文档。** 能机械验证的一律写成契约测试（本仓已有 20+ 个），文档只留一行指针。
   文档会被截断、被忽略、会腐烂；测试不会。写入 `AGENTS.md` §0 元规则第 1 条。
2. **`AGENTS.md` 只放两类内容**：① 每次都必须生效的行为约束（§0.1 / §0.2）；②「何时必须读哪份主题文档」的索引（§4）。
3. **体积硬指标 32 KiB**（默认预算的一半，留一倍余量），由 `test:agents-md-guard` **硬断言**——超限即 CI 失败，
   从机制上禁止"再加一条"。这条是把"别再涨回去"变成可执行约束的关键。
4. **红线按「有无守卫」分两类**：有守卫的压成一行「规则 → 守卫命令」（§0.2，遵守了自然绿）；**没有守卫的才是必须常驻的**
   （§0.1，全靠动手前对照），并逐条指向实现位置。

## 守卫升级（`tests/agents-md-injection-guard.test.js`）

- 新增**硬断言 `AGENTS.md ≤ 32768`**（不再只对 64 KiB 告警、只对 128 KiB 失败）；
- 关键章节名同步为新结构（§0 元规则 / §0.1 红线 / §0.2 有守卫的规则 / §1–§5）；
- 红线关键词保留原有 5 个（含 `inventory_containers.remaining_qty`、`syncStockFromContainers`、`X-Request-Key` 等，
  重写时曾漏掉其中两个，已补回正文——**这正是该断言的价值**）；
- docs 引用存在性、`npm run X` 脚本存在性检查保留，但**防扫描失效的下限随引用数下调**（docs 引用 40 → 12、
  npm 引用 30 → 10，避免文件瘦身后守卫自己假失败）。
