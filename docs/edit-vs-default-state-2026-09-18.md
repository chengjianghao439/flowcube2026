# 编辑态与默认态区分 + 保存反馈（2026-09-18）

## 背景（用户反馈）

用户提出：**“有的页面编辑和默认的状态是一样的，需要改为编辑状态和默认状态不一致，保存有反馈。”**

排查（本机开发模式实测 + 代码核对）确认的问题：

1. 基础资料/主数据的编辑弹窗与「新建」弹窗除标题一行字外几乎完全一致（实测客户编辑弹窗与新增客户弹窗），用户看不出自己是在编辑已有记录。
2. 单据/商品表单的新建态与编辑态共用同一表单，区别只在 ActionBar 文案；编辑态下修改了字段也没有任何「未保存」提示（`isDirty` 只在新建态显示）。
3. 编辑态一打开就可能被误判为“未保存”：销售/采购明细在编辑态会异步拉取商品多计量单位并写回 `units`，而脏检查直接 `JSON.stringify(items)`，把这次投影回填算成了用户改动。
4. 保存反馈不齐：采购单新建、调拨单新建保存后直接关标签/跳转，没有任何成功提示（销售单的新建/编辑/改单提示在 `hooks/useSale.ts` 里，属重复检查后的既有能力，未改动）。

## 本次改动

### 共享件

- 新增 `frontend/src/components/shared/EditModeBadge.tsx`：导出 `EditModeBadge`（编辑中）与 `UnsavedBadge`（未保存）。配色复用 `lib/statusTone.ts` 的 `active` / `warning` 档，不新增硬编码颜色。
- 新增 `frontend/src/lib/editMode.ts`：
  - `editTargetLabel(row, keys)`：取行对象的 `code · name` 作为“正在编辑：…”描述；
  - `dirtyItems(items)`：剔除明细行的 `units` 投影字段，供脏检查使用。

### 编辑态标识（页面级）

- 商品 `pages/products/form.tsx`：编辑态显示「编辑中」+ 编码，按钮 `保存修改`；未保存时显示「未保存」。
- 销售单 `pages/sale/form/index.tsx`：新建/编辑/改单三种视图的未保存提示改为统一 `UnsavedBadge`；编辑态加「编辑中」，改单态加「改单中」，编辑态主按钮改为 `保存修改`。
- 采购单 `pages/purchase/form/index.tsx`：编辑态加「编辑中」，按钮 `保存修改`，未保存提示在新建/编辑态都显示。
- 调拨单 `pages/transfer/form/index.tsx`：同上；并把编辑态脏检查改成与进入编辑时的快照比较（原来“任意字段非空即算改过”会让编辑态恒为脏）。

### 编辑态标识（弹窗级）

- `BaseCrudPage`（承运商/供应商/仓库/库位/货架/分拣格/费用类别等）：编辑态标题加「编辑中」，标题下显示“正在编辑：编码 · 名称”，主按钮由 `保存` 改为 `保存修改`；新增可选 `formIdentity` 覆盖身份取值。
- 独立编辑弹窗：客户（`CustomerFormDialog`，另加「未保存」）、部门、分类、用户、审批流、财务账户、报销单、发票、PDA 设备 —— 均为“编辑中标签 + 正在编辑对象 + 保存修改”。

### 保存反馈

- 采购单新建保存后补 `toast.success('采购单已创建')`；调拨单新建补 `toast.success('调拨单已创建')`。
- 销售单不新增提示：`useSale.ts` 已有「销售单创建成功 / 订单已保存 / 改单已提交，等待仓库确认」，实测保存时只应出现一条。

## 第二轮：打开即编辑的配置页改成「默认只读 + 编辑态」（用户澄清后）

用户澄清：“（我说的）直接就是编辑页面，点击保存只有一个成功提示，没有反馈。”即这些页面**打开就是编辑表单**，保存后除了 toast 页面没有任何变化。修正后的口径：**默认态只读查看 → 点「编辑」进入编辑态 → 保存成功后自动回到默认（只读）态**，页面状态本身的变化就是“保存生效”的反馈。

落地页面与行为：

| 页面 | 默认态 | 编辑态 | 保存后 |
|---|---|---|---|
| 系统设置 `settings/index.tsx` | 参数按「标签 + 值」只读展示；Logo 仅预览，提示“点「编辑」后可上传” | 「编辑中」标识 + 输入框 + 上传 Logo + `保存修改`/`取消编辑` | 回到只读态 + `保存成功` |
| 权限管理 `permissions/index.tsx` | 只按分组展示该角色**已授予**的权限胶囊 + “共 N 项权限” | 全部权限可点选 + `保存修改`/`取消编辑` | 回到只读态 + `权限已更新…` |
| 快递账号绑定 `carrier-accounts/AccountBindingForm.tsx` | 月结账号/常用发货服务/送货方式只读展示 | 表单可输入（沿用原锁定规则：启用自动下单后需先暂停）+ `保存修改`/`取消编辑` | 回到只读态 + 父页 `月结资料已保存` |
| 盘点 ABC 规则 `stockcheck/abc.tsx`（分批盘点规则） | 周期/上限/启用只读展示 | 输入框 + 勾选 + `保存修改`/`取消编辑` | 回到只读态 + `分批盘点规则已保存` |

配套行为：`取消编辑` 一律丢弃改动回到基线；“是否改过”只在编辑态参与脏检查；权限页在编辑态切换角色会先确认（避免静默丢失未保存勾选）；系统设置无修改权限时只显示只读值，不出现「编辑」入口。**保存回执只在“提交内容仍是最新输入”时才回到默认态**——保存期间又改了内容就留在编辑态并保留关闭保护，不能把后续草稿当成已保存（销售单改单与 ABC 规则此前已有同类守卫测试，本次推广到这四个页面；`AccountBindingForm`、`settings`、`permissions` 用最新值 ref 比对，`abc.tsx` 用 `latestRulesRef`）。

实测（本机开发模式，验收临时账号）：

- 系统设置：默认态显示“当前为查看状态；需要修改请点右上角「编辑」。”+ `编辑`；编辑态显示「编辑中」+ `保存修改`/`取消编辑`；点 `保存修改` 后回到只读态并出现 `保存成功`。
- 权限管理：默认态只显示已授予权限；编辑态全量可点选；保存后回到只读态并出现 `权限已更新，用户下次登录生效`（保存内容与基线一致，属无变化写入）。
- 快递账号绑定（德邦）：默认态只读展示三项资料 + `编辑`/`启用自动下单`；编辑态显示「编辑中」+ 表单 + `保存修改`/`取消编辑`，取消后回到只读态。
- 盘点 ABC 规则：默认态周期/上限为文本、启用为状态胶囊 + `编辑规则`；编辑态出现输入框与 `保存修改`/`取消编辑`，取消后回到只读态；点 `保存修改`（内容不变的无变化写入）后回到只读态并出现 `分批盘点规则已保存`。

## 限制与待确认

- 快递账号绑定的**保存成功**回默认态未走完整实测（本地没有可用月结账号测试数据，不能拿假账号写入）；逻辑上保存成功即 `setEditing(false)`，且组件 `key` 含 `data.revision`，会重新挂载为默认态。
- 快递账号绑定编辑态下若绑定数据被后台刷新且 `revision` 变化（例如他人改过绑定），组件会因 `key` 变化重新挂载并回到默认态（未输入的编辑态会被打断，已输入的草稿由父页 `editingData` 冻结保留）；点「刷新开通状态」只 refetch、`revision` 不变，不会打断编辑。
- 采购/调拨的编辑态标识只做了代码与类型检查，未在本地造单走完整流程；桌面客户端与 PDA 未验证（本次改动只在 ERP 前端）。
- 未提交、未发布；工作区另有并行会话的收付款弹窗重构改动，本改动不涉及 `components/shared/payments/`、`ui/dialog.tsx`、`AppDialog.tsx`。
- 行为守卫测试随契约更新：`carrier-accounts/AccountBindingForm.test.tsx`、`carrier-accounts/index.test.tsx`、`stockcheck/abc.test.tsx` 改为“默认只读 → 点编辑 → 保存回默认态/取消丢改动”，并新增一条绑定页编辑态用例；全量 `vitest run` 81 文件 / 394 用例通过。
