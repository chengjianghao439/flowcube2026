# 全系统业务列表取消页面分页

ERP、桌面和 PDA 的业务列表、查找弹窗不提供分页操作。筛选条件内的全部记录在一个连续列表查看，不再有页码、每页条数、跳页、上一页/下一页或加载更多。日期、仓库、状态、关键词等原有筛选条件继续生效，取消分页不等于取消筛选。

## 实现

- `api/allRecords.ts` 负责自动聚合标准 `{list, pagination}` 信封。`payloadClient.get` 对列表参数统一从首批开始，默认批量 200，并使用服务端实际 pageSize（例如审批上限 100）继续读取。没有分页信封的详情、数组和报表响应原样返回，二进制下载沿用既有处理。
- 只有全部批次成功才返回合并列表，保留服务端 summary、statusCounts 等信息，不累计重复的全局汇总。批次数量变化、重复批次、提前空批或传输失败均报错，禁止把首批或残缺数据当全量成功。
- 整次 GET 聚合固定登录 sessionGeneration 与会计 companyId；后续批次沿用原请求关键词、日期、仓库、单据状态和其它过滤参数。鉴权与业务范围校验由每次原接口执行。取消请求后停止后续批次。
- 审批待办引擎补真实计数与有界批次，移除先固定截取 100 条再做页面切片的错误；通知数量直接使用同一计数，不读取前 100 条估算。审批权限、任务匹配和状态推进不变。
- 后端继续执行参数化 SQL 和单次查询上限；各有界列表对相同创建时间、名称等主排序补充唯一 ID，库存聚合使用商品/仓库组合，避免跨批次排序不确定。没有数据库迁移和业务数据写入。
- 普通列表由 `ListSummary` 显示真实总数，删除 Pagination、PaginationArrow 及旧分页测试。BaseCrudPage 改为 recordUnit，不再接收页面分页配置。会计凭证/发票、商品查找、风险明细分别移除独立分页，搜索 API 自动读完各类别游标，并固定原登录会话。
- 首页待办摘要使用明确的 summary 模式保留 5 项摘要及“查看全部”目的地；Top 排行、报表聚合、纸张打印分页不受本次业务列表规则影响。后端导出上限与批量写入上限沿用原规则。
