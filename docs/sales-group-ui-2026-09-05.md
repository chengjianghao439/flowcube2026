# 销售分组页面样式重构

用户将范围从销售订单关联页面扩大到导航中的整个销售分组；本轮纳入销售退货。桌面样式和信息组织为范围，不修改销售、退款、授信或物流业务动作。保留前几轮仪表盘与销售页面未提交改动。

| 导航入口 | 本轮处理 |
| --- | --- |
| 销售管理 | 复用此前统一的列表、新建/编辑/改单、详情和全局选品器，复验 |
| 销售退货 | 列表单号与时间集中展示；新建三列订单信息、商品身份独立分列列；详情完整规格；查询紧凑排列 |
| 超额放行申请 | 申请单与时间集中展示、保留金额快照与审批操作；查询弹窗加宽紧凑排列；驳回原因从浏览器 prompt 改为统一弹窗，显示申请身份、300 字上限和提交中禁用 |
| 物流运单 | 运单与创建时间、快递单与承运商分别合并展示；明确日期与当前加载数量；详情主次栏、长字段换行；录号与查询表单加宽 |
| 客户管理 | 客户编码与名称、联系方式分组；列表真实总数；新建/编辑按资料、结算与授信分区；价格绑定与导入区域统一层级 |
| 承运商管理 | 承运商身份合并展示、明确电子面单开通状态；新建/编辑改为宽双列，资料与面单配置分区 |
| 客户对账门户 | 选择客户后才显示表格；统一单一空状态和明确主操作；查询失败有重试，保留只读 |

`RecordIdentity` 是纯展示组件，复用于客户、承运商、运单、退货和放行申请，不承担查询或业务状态。销售退货没有独立编辑能力，保持现有新建/详情/确认/取消入口。共享 ReturnQueryDialog 的紧凑纵向布局也作用于采购退货，未扩展采购业务。运单仍沿用现有最多 500 张加载口径，文案明确当前显示数量，不冒充全量总数；本轮不扩展分页接口。非销售导航下的运费对账、财务管理及供应商门户不在本轮。

## 验证

本轮在 Codex 内置浏览器复用有效本地会话，以 1600×1000 桌面视口核对：

- 客户列表、新建表单与表单字段标签；承运商列表、新建表单、面单开关及展开后的全部配置。
- 销售退货新建选品（SKU0001 的名称、编码、供应商型号、型号、颜色、单位、数量、单价与金额）、列表，以及已完成的 SR20260902002 详情/作业进度。未保存的测试商品行已移除。
- 物流当天空列表、不限日期返回 4 张运单、DEMOWB003 失败详情与录号弹窗（空值保存禁用）。日期通过既有日历清除按钮操作。
- 放行申请空列表与发起申请弹窗（未选订单禁用提交）；当前数据无待审批申请，未通过真实审批操作验证驳回提交。
- 对账门户未选客户时只显示一个引导空态；选择北京智联后显示该客户对账列表空态，没有重复引导。
- 销售管理主列表、快捷查询和新建入口仍正常显示。
- 客户、承运商完整表单、销售退货新建和门户空态已截图目视核对。物流详情修复标题嵌套后重新加载，没有新增相同浏览器警告。

所有界面验收使用本地开发服务；不保存客户/退货单、不审批、不取号、不导入文件、不物理打印。编辑表单共用已核对的新建布局，未逐个执行保存；无真实对账行和待审批数据的状态不作为已完成业务回归。窄屏与生产部署不在本轮。

共享 PageHeader 的 description 容器从 p 改为 div，以合法容纳物流状态 Badge 等 ReactNode；修复浏览器 validateDOMNesting 警告，文字样式不变，所有使用该容器的页面沿用相同外观。
