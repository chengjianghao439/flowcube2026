# 经营 KPI 口径与页面修复

## 当前规则

- 销售按 `sale_date`（业务日期）筛选已出库订单，净额为原值扣非负整单折扣后下限零，成本优先明细成本快照。先聚合成每单一行，避免明细 JOIN 将整单金额重复累计；当期/上期/趋势/分仓使用一致口径。
- 销售范围沿用原单的头仓及全部明细仓权限；分仓展示仍归入订单头仓，未改为出库实物分仓。
- 回款仍按 `payment_entries.payment_date` 统计 type=2 分录。无限制账号保留全部应收分录，包括手工及无来源款；受限账号只读能关联到非删除、全部仓库有权销售单的回款，不要求来源销售状态为已出库。手工无仓库来源的款项不猜测归属。该规则只影响 KPI 读取，不改变原财务账款或权限。
- 月区间使用当月首日（含）至次月首日（不含），覆盖二月及月末全天。趋势从起始月到所选月末，不扫描未来月份，空月补零。`period` 必须为有效 YYYY-MM，`offsetPeriods` 为 -36..36 整数（0 为本期自比，默认 -1），`months` 为 1..36 整数；超出 MySQL 1000..9999 年日期窗口时返回 400。
- 环比为（本期−上期）/上期绝对值；上期为零、本期非零时保持不可计算，双方零则为 0%。分仓占比按各仓销售净额合计计算，零合计为 0%。
- API 保留 `gmv` 字段，页面名称为“销售净额”。此页业务日期与利润分析的开单创建时间不同；均未加入销售退货净额，不属于会计利润。

## 页面

复用报表错误反馈：首次失败不展示假零/假空；刷新失败保留图表和分仓数据并警示，恢复成功后清除。隐藏经营视图不主动查询。月份选择按北京时间生成，负毛利使用红色。

电脑检查发现窄窗口顶栏菜单换行后压住工作区标签：原容器固定 48px，800px 窗口测得菜单底部 99px、标签顶部 48px。改为最小 48px 并随菜单内容增高；小于 1024px 时菜单移到工具区下一整行，减少挤压，保留标签独占下一行；不修改菜单项或导航权限。修复后同窗口菜单底部 87px、标签顶部 91px，无覆盖。
