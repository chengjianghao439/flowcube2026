# 电子面单与快递对接：现行实现与后续范围

2026-09-06 已按当前工作区核对并替换旧设计草案。旧稿中的“没有物流模块”“平台按相同订单号自动幂等”“每箱独立请求”和“估算重量”不再适用；历史设计可查 Git。正式账号联调与部署状态以本次验收记录为准。

## 已有能力

物流模块已有运单列表、详情、手工录号、取号队列、轨迹表和运费对账。承运商保存平台、月结号与凭据引用，密钥只从服务端读取。既有 `mock` 用于演示，`kdniao` 沿用原适配器；它们不代表顺丰、德邦已真实开通。

## 顺丰、德邦月结直连

- 通过官方接口下单和查询原单，采用各自签名规则，避免强制购买聚合平台套餐；官方费用与权限仍以月结合同为准。
- `packDone` 校验整批打包及箱贴完成后，同事务按仓库任务读取 `packages.status=2`。每批最多 30 箱；同一批一个内部订单号，返回并保存全部母子运单号。旧 `UNIQUE(package_id)` 只覆盖原来的单箱流程，直连批次由 `direct_batch_key` 唯一键保护。
- 箱数自动填写，前端不能改件数或箱子归属，不采集重量。按用户最新约定，顺丰 `totalWeight` 和德邦 `packageInfo.totalWeight` 均默认传 1（kg）。顺丰字段为本批总重，德邦字段为单件/均重；两者下单字段都固定传 1，不按箱数累乘。该默认值不是实际称重，不写入实重或运费账单。旧免预录重量配置不再使用。
- 默认发货产品在承运商设置，销售草稿可覆盖。普快/航空不能仅凭俗称推导官方产品编码，使用月结合同开通的产品。PDA 不决定承运商与发货产品。
- 寄件信息来自发货仓库，收件信息来自销售单；省市区只对完整明确地址拆分，无法识别时由运单详情补全，不能猜地名。下单前可补充资料，已提交报文不可改写。
- worker 先锁任务再领取运单，复查取消/改单状态与真实箱子。数据库提交请求快照后才执行外部 HTTP，回写通过请求租约 CAS，防止过期进程覆盖后续结果。
- **不能假定平台重复下单幂等。** 德邦同渠道号重复 create 可能追加子件。超时、进程中断、回写失败一律进入状态 6“下单待核实”，只查询原单；最多自动查询 5 次，随后人工触发查询。未发送的配置错误为状态 4，可修正后提交。
- 已提交的直连单不能手工替换单号或仅在本地作废；真实取消须通过快递官方处理。已提交箱子变更时阻止自动重建原批次，先核实原单，当前没有自动取消及取消确认同步接口。

## 打印、轨迹与对账边界

下单回执不是可打印电子面单。直连回执标记“请通过快递官方打印面单”；本轮不伪造 ZPL、不向标签打印队列塞不完整面单。平台正式打印接口、母子件与实箱映射验收、物流轨迹订阅以及实际重量/运费回传仍需另行开通和联调。现有手工运费账单可录入承运商最终确认的实重与运费；这不是发货时的重量输入。

配置示例、官方文档及当前验证记录统一维护于 [顺丰/德邦官方直连](../direct-express-2026-09-06.md)。现行数据库扩展为 `237_direct_express.sql`，后续变更须新增迁移，不修改已执行迁移。
