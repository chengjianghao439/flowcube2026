# Flowcube 功能设计文档集（proposals）

> 这批文档是"**先设计、全部定稿后再动手**"的产物，由 2026-07-29 对着当前代码逐条调研后落笔。每份都同构为 11 节（背景与现状问题 → 目标/非目标 → 与现有系统的关系 → 数据模型 → 流程/状态机 → 后端清单 → 前端清单 → 权限 → 分阶段 → 验证 → 风险），现状结论尽量指到 `文件:行`。
>
> **迁移编号说明**：文档里出现的迁移号（如 01 的"迁移 151"）是**示意**。实际按实现落地顺序顺延——同一时刻只有一份能占 151，多份并行实现时依次取"当前最大 +1"。
>
> **审校结论**：12 份已交叉核查，无违反库存不变量/状态机/权限三处同步等硬约束的设计；无迁移编号撞车。可作为实现依据。

## 相互依赖（实现前必看）

- **11 依赖 01**：需求预测复用 01 的 `product_stock_policies` 与日均销量/在途口径。11 先行则需把 01 的表一并带上。
- **02 衔接 11**：采购计划建议可流入请购单。
- **07 复用退货质检**、**08 复用全盘内核**、**05/06 复用现有事务与幂等**：这几份是"在现有内核上加薄层"，风险最低。
- **03 是全链路改造**：数量单位贯穿采购/收货/库存/销售/出库/盘点/退货/结算，风险最高，务必按"先只读展示→逐链路放开录入→最后 PDA"分阶段。

## 建议实施顺序（三波）

**第一波（高价值 / 低风险 / 有前置价值）**
- 01 安全库存与补货建议（无依赖、价值高、是 11 的前置）
- 12 的 ②④：权限码单一事实源生成 + 迁移编号唯一校验（加"生成/校验"，不动业务，性价比最高）

**第二波（🟠 独立、在现有内核上加薄层）**
- 07 收货质检（结算不改、复用范式，最稳）→ 05 信用额度 → 02 请购审批 → 06 电子面单

**第三波（高风险 / 大工程 / 需专项立项）**
- 03 多计量单位（全链路，灰度）、11 需求预测（依赖 01）、04 序列号、08 循环盘点、09 库龄、10 会计总账（先只做导出对接，别急着自建）

## 待你拍板的关键取舍

- **10 会计总账**：自建轻量总账 vs 只做凭证导出对接金蝶——文档推荐后者，需你确认方向再展开。
- **03 多计量单位**：改造面最大，确认要做再排期，且必须灰度。
- **06 电子面单**：对接哪类快递平台（聚合 vs 直连）需业务侧定。
