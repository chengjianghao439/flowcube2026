# 待办中心巡检入口清理（2026-09-08）

## 已确认范围

用户明确此前已经决定不做巡检功能。本次清理待办中心、首页我的待办和通知中的遗留巡检入口；不恢复独立异常工作台。

- 移除异常销售单、异常任务、库存异常、近期高风险问题四类卡片，移除系统巡检通知。
- 待办查询不再读取 system_health_logs 或扫描库存负数充当巡检待办；不再重复统计同一批高风险记录。旧响应 managementCount / healthAnomalies 保留为 0。
- 保留待收货、待上架、打印失败待补打、待出库、低于进价销售单及订单履约事项；普通财务提醒继续保留。
- 前端统一排除旧服务/缓存返回的巡检卡片与通知；处理入口必须是注册 ERP 路由，并满足目标页面权限。空岗位分组不展示，首页摘要重算可访问待办数，按 P1 在前排序。
- 异常工作台旧地址仅兼容历史书签，不能作为当前待办的处理动作；历史巡检日志不删除。本次不改运维告警、数据库或生产服务。

## 根因

旧报表聚合固定返回巡检卡片，异常工作台地址只是待办中心别名，点击后仍回到本页；管理异常与高风险卡片复用相同日志。页面没有校验目标路由权限，导致有 report.view 却无原业务权限时出现无法打开的按钮。系统巡检提醒还错误指向 PDA 扫码异常分析，两者不是同一类数据。
