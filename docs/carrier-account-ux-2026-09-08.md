# 快递账号与承运商资料衔接优化（2026-09-08）

本文保留实现时的验证记录；相关代码已纳入 v0.9.11 发布准备，实际发布结果以 `docs/release-v0.9.11-result.md` 为准。

## 核对结论

两个页面原本就读取和修改 carriers 同一条记录。快捷新增提交 platformCode，后端也保存该字段，没有发现“新增所选公司被后端丢弃”的证据。此前界面把承运商管理的平台选择放在启用取号之后，名称与平台容易混淆；绑定详情与承运商列表的缓存失效范围不同，在另一页修改后可能显示旧月结资料。

## 当前交互

- 承运商管理始终展示「快递公司 / 对接平台」，未启用自动下单也能先选择保存。列表展示平台、月结号，并可打开对应承运商的「管理月结账号」。
- 快捷新增改称「新增承运商账号」，说明会同步建立承运商档案，已有资料从左侧选择。平台只选一次，不用在另一页再次建立。
- 绑定详情直接显示已保存的顺丰/德邦及「承运商资料已带入」。只对未设置平台的旧档案显示「补充快递公司」，说明补选保存后两个页面共用。不通过名称推测平台，不迁移或修改现有业务资料。
- 绑定详情缓存纳入 carriers 统一刷新范围。另一页保存后，未编辑的表单更新；有草稿则保留草稿及原 revision，保存时仍由后端拒绝过期覆盖。已有绑定大页可响应新的 carrierId 定位，有草稿时需要确认切换。
- 按用户进一步要求，移除开通步骤、长篇技术说明和重复提示。保留月结账号、常用服务、德邦送货方式，以及一条当前状态。顺丰内置官方常用产品，无需先手填产品列表；特殊合同选项可覆盖。

本项不配置生产密钥、不登记未经验证的账号、不启用自动下单、不发起快递订单；绑定页不提供删除入口；承运商管理页的删除及既有解绑和后台验收守卫保留。
