# 首页卡片排序修复（2026-09-08）

## 根因与当前规则

布局保存接口按原样保存 widgets 数组顺序，但首页阅读态按固定 DASHBOARD_SECTIONS 分类后再次拆分 KPI 与其他卡片，覆盖了编辑态顺序。因此系统版本即使拖至顶部，保存后仍落在最后的系统信息区；同类业务卡与 KPI 交错也无法保持。

现在阅读态与编辑态使用同一份已保存的可见卡片序列和四列网格、卡片跨度，移除强制分类重排及固定分区导航。全部卡片均可跨分类排序，系统版本也可排第一；保留不同类型高度、组件库分类、默认/推荐排版、权限过滤及历史布局兼容。数据存储格式和保存 API 不变，已保存的自定义顺序在刷新后直接生效。

## 验证

新增两项页面回归，修复前实际失败：保存的跨分类/指标交错顺序、系统版本末尾拖至首位后保存与重新挂载。页面与布局注册表共 6 项回归通过；TypeScript、相关 ESLint、ERP 构建与 diff 检查通过。

本地开发浏览器使用验收账号添加系统版本卡片，通过页面 HTML5 拖动事件将其从末尾移到第一张，再点击实际保存按钮。读取保存 API 的 widgets 顺序与展示 DOM 顺序一致，均以 system-version 开头；刷新后仍为第一张。验收后恢复该本地账号原来的默认展示布局并关闭本任务浏览器；未变更用户生产布局。本次工作区修改，未发布生产。
