## 现行规则与修复

- 塑料盒新建只接受正整数商品、仓库及可选库位 ID，备注为最多 500 字文本；商品、仓库、库位启用与归属继续由事务校验。空盒数量为 0，不增加库存。该模块没有编辑接口，回归覆盖实际创建、读取、删除与流水入口。
- 波次按商品合计任务数量，以成员中最早明细的显示快照为波次显示值，各任务原始快照不变。同商品历史名称/编码不同不能被拆成重复商品行并触发 `(wave_id,product_id)` 唯一键冲突。
- 创建波次先检查每个成员任务的仓库范围，再返回绑定、状态等业务错误，防止越仓请求获取任务或波次编号。
- 波次完成时按任务 ID 锁定成员，所有活动成员先检查待实物归还/待改单标志，命中时沿用单任务入口的 409 错误并整批回滚；再只把尚处于拣货中的任务推进到待分拣；已经通过单任务/PDA 入口进入分拣、复核、打包、待出库的成员保留现状，终态成员仍跳过。波次完成不扣库存、不解锁实物容器，不代替后续复核、打包和出库。
- 波次取消仍复用仓库任务取消。含进行中的销售关联任务时返回 `SALE_ORDER_CANCEL_REQUIRED` / 409，要求从销售订单取消；不能绕过整单预占和实物归还保护。非销售任务若有实物锁，取消波次会发起成员逆向归还，保留执行状态和容器锁，等待 PDA 实物确认。
- 活动波次详情 `GET /picking-waves/:id` 默认会刷新 `picking_wave_items.picked_qty` 投影，因此不是纯只读请求；其数值来自任务明细，不反向改写任务或库存。
