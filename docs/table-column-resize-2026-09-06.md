# 公共表格列宽交互

## 当前行为

用户确认采用“拖哪列只改变哪列”的方式，统一应用于使用 `DataTable` 的业务列表与单据明细。

- 分隔线位于表头右边缘，整高 12px 抓取区域，悬停、聚焦和拖动时显示强调线。拖动表头文字仍为调整列顺序。
- 拖动仅改变目标业务列，其他列保持开始时的实际像素宽度，勾选列固定 56px、不参与快照。单列表格同样可调整，业务列最小 80px；操作列同样支持调整顺序和列宽，不固定在右侧。
- 所有业务列（含操作列）按实际顺序一起滚动，不使用右侧吸附定位；极窄操作列内的按钮区域可以横向滚动，不遮挡相邻内容，菜单仍使用 Portal 弹出。
- 总宽度随目标列一起改变，超过容器时横向滚动；手动缩窄后不强制撑满容器，避免浏览器自动放大其他列。
- 双击分隔线适应当前已加载的表头与内容，含被截断的文本与表单控件；加上单元格内边距和 4px 字体／小数像素余量。自动适配最多 800px，超长内容沿用换行或截断；手动拖动不受该上限限制。
- 2026-09-08 按用户要求移除表格上方“恢复默认列宽”按钮及整条工具栏，已保存列顺序和宽度保持原样。分隔线可用 Tab 聚焦，左右方向键调整 10px，Shift 加方向键调整 40px，Enter 适应内容。
- 鼠标移动只通过 requestAnimationFrame 合并更新 colgroup/table 的 DOM 宽度，松手一次更新 React 布局状态并保存；不逐次重新执行明细 render。未移动的点击不保存布局。
- Escape、窗口失焦、组件卸载和列结构／存储目标变化均取消预览、撤销未提交宽度、取消待执行动画帧，并解除监听和恢复光标／文本选择状态。

## 兼容与边界

存储仍为 `flowcube:table-columns:*`，新增 `widthUnit` 区分像素与比例。旧列顺序数组及 `{order,widths}` 均兼容；旧比例表按百分比读入，第一次手动调整或自动适配后保存全部实际像素宽度和 `widthUnit: 'px'`。未保存过宽度时使用页面原有比例或固定宽度布局。存储不可用时仍可在本次页面内调整。

父页面生成相同列键的新 columns 对象不会重新载入旧布局。默认存储路径固定于表格挂载页面，避免 keepAlive 后台页面串用当前页面路径。旧设置过滤失效列、非法宽度和重复列键。

保留此前修复的勾选列索引、实际宽度快照、刷新打断拖动和卸载监听问题。已移除相邻列补偿及“单列不允许调整”的旧方案。此次不改业务数据、打印模板编辑器或未使用 DataTable 的原生表格。
