**已修复（窄修，未重构引擎）**：

1. **P0-5 撤回收货吞掉在途调拨容器**（`inbound-tasks.void.js`）：整箱调拨**复用同一容器行**（`transfer.service.js` 的 scanOut 只改 `warehouse_id/status/transfer_order_id`），`remaining_qty == initial_qty` 恒成立、`locked_by_task_id` 为空，两道既有守卫全部放行；置 VOID 后货从账上静默消失且不留流水，调拨单永久卡在「在途」。修法：容器查询补 `transfer_order_id`，非空即 409。**既有注释声称「已被调拨动过」会被拦，与实现不符，这次把注释兑现了。**
2. **P0-1 盘点扫码核销拣货锁定容器**（`stockcheck.service.js`）：扫码盘点的账面容器查询缺 `locked_by_task_id IS NULL`，而 `deductFromContainers` 早有该条件——**非扫码路径安全、扫码路径是后加分支绕开了闸门**。修法：补齐同口径条件，并对被跳过的锁定容器打 `[StockcheckScanGuard]` WARN 留痕（不写 `inventory_logs`，因为未做任何变动）。
3. **P0-4 补占换仓孤儿化预占**（`sale.service.js` reserveStock）：行已有预占时禁止更换发货仓库，返回 400 `RESERVE_WAREHOUSE_CHANGE_NOT_ALLOWED`；前端 `ReserveAllocationDialog` 同步禁用该行仓库选择并给出提示。**这是有意的行为变更**：想换仓必须先释放该行预占再重占。未选「自动迁移旧仓预占」是为了不在本轮改动引擎的加锁面。
4. **P0-3 销售收入凭证毛额入账**（`voucher-engine.js` buildSaleRevenue）：本文件头声明「毛额 + 退货单独冲 → 净额 = payment_records(type=2)」，而应收口径还扣整单折扣，**折扣没有独立单据因而没有单独冲销凭证**，导致 1122 恒比子账多 Σ折扣。修法：复用销售侧同一函数 `calculateDiscountApplied`（按已发原值/订单原值比例分摊）在收入凭证内净额化，税额夹到折后净额。`buildSaleRevenue` 已加入导出供测试。
5. **P0-2 库存写接口缺仓库范围**（`inventory.controller.js` / `inventory.service.js`）：容器的移库与拆分补 `assertInScope`；移库同时校验目标库位与容器同仓（跨仓库位会让容器带错误位置在册）。
6. **同形态 P1 收口（第一批）**：`resync-stock` 由 `inventory.trace.view` 改为 `inventory.adjust`（它是重算缓存与预占账的**写操作**），前端按钮按 `INVENTORY_ADJUST` 隐藏，避免只读账号点出静默 403；`PUT /users/:id/warehouse-scope` 接入 `withLockedTarget` 并新增自我提权守卫 `USER_SCOPE_SELF_FORBIDDEN`（仓库范围语义为「无行 = 不限仓」，限仓用户清空自己那行即获得全仓读写）。
