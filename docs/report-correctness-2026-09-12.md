# 利润与库存报表修复（2026-09-12）

## 问题与现行口径

- 原销售汇总将订单与明细 JOIN 后直接累加订单额，一单多行会重复；原订单/商品毛利没有一致扣整单折扣。修复按已完成销售单的开单日期读取，每单只计一次；销售净额沿用业务规则 `max(0, total_amount - discount_amount)`，商品按明细金额比例分摊净额，成本优先明细快照，旧数据回退链保持不变。属于经营估算，不是会计利润表。
- 原库存与滞销卡片从前 30 条列表累计，卡片误称全部金额/数量。现在独立汇总全部符合条件的数据，销售和商品各显示毛利前 20 条，库存/滞销各显示金额前 30 条。
- 原滞销查询读取全仓库存与出库，可能泄露仓库范围外的数据，或用无权仓出库掩盖授权仓滞销。现在库存与最后出库使用同一授权仓库集合；销售整单还需全部明细仓授权，与销售原单权限一致。
- 库存按商品 ID + 仓库 ID 分组和渲染，同名仓库不会合并，同商品不同仓库不会共用行标识。估值仍按商品成本价（缺失时参考售价），沿用 `getInventoryDisplayProjectionSql()` 读取引擎维护的 `inventory_stock` 展示缓存，没有更改库存事实或成本引擎；本次未验证容器与缓存账实一致性。
- 本页滞销按授权仓库合并商品判定：仍有库存，且最近 90 天无出库，包含无出库记录。卡片打开本页已有 API 对应明细；库龄页则按商品/仓库判定并使用移动加权成本估值，两者不可直接等同。库龄/效期原有算法保留。

## 页面行为

- 首次读取显示加载状态和未知金额占位；失败提供重试，不伪装成金额为零或暂无数据。
- 有缓存的刷新失败保留原列表和卡片，同时明确提示显示上次成功数据；恢复后清除提示。
- 库龄和效期各自显示失败信息；未打开效期时刷新只读库龄。效期失败不遮挡已有库龄汇总。
- 日期注明仅作用于销售开单时间；库存和滞销为当前值。负毛利用错误语义色；滞销卡片可键盘操作；桌面四列、较窄窗口两列。

**订正（2026-09-27）**：上一版此处写「未把创建但不被工作簿消费者使用的 `summaryRows` 当作实际导出内容」——当时 `payload` 顶层那个同名数组确实是**死字段**（`export.controller.js` 只把 `payload.sheets` 交给 `exportMultiSheetXlsx`，而它只渲染 `sheet.summaryRows`，注释写着"第一页顶部附加合计行"却从未生效）。现已**订正为真正生效**：五条汇总（销售额/销售成本/销售毛利/库存金额/滞销库存金额）并入首个 sheet 的 `summaryRows`，并按下面新增的成本口径补充说明。

**报表成本口径（2026-09-27 P2）**：利润分析与经营 KPI 的**成本**表达式去掉 `COALESCE(..., p.sale_price, 0)` 这一级回退——快照为空且 `cost_price=0` 时拿**售价**当成本会把毛利系统性压低。保留迁移 119 已定的「非零现价进价」估算，并把两种非快照情形分开暴露：`estimatedCostAmount`（按当前进价估算的金额）与 `missingCostLineCount`（完全无成本的明细行数）。页面与导出据此提示：**这是经营估算口径，可能偏高，与凭证侧的会计成本（快照记账）口径不同**。库存估值 `total_value` 不在"成本 SQL"范围，仍沿用原口径。回归 `npm run smoke:report-cost-basis`（含真实生成 xlsx 的读回断言）。

**导出渲染订正（2026-09-27）**：`fillSheet` 原先用 `ws.columns = [{ header, ... }]`，ExcelJS 会据此把**整行表头钉在第 1 行**——当 sheet 顶部有汇总块时，A/B 之外的列会留下"幽灵表头"（实测 C1 是「仓库」而真表头在 A4）。现改为只给 `key/width`，表头统一由 `headerRow.values` 在 `startRow` 写。
