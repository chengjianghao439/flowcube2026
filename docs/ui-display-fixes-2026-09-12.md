# 全模块页面验收：显示与大列表性能修正

本记录对应 2026-09-12 本地开发模式页面验收发现的时间显示、打印环境提示与大列表性能问题，覆盖商品改价、两个门户、货架、打印机管理、条码打印查询和操作日志。修改位于 `operations-optimize-20260912` 工作树，本文不代表已发布或实体打印验收。

## 现行行为

- 商品改价申请列表的“申请时间”使用 `formatDisplayDateTime`，统一按北京时间显示。接口的 `2026-08-22T12:26:12.000Z` 显示为 `2026-08-22 20:26`；不修改服务端时间值或审批规则。
- 供应商到货门户和客户对账门户的“创建时间”同样使用 `formatDisplayDateTime`，不再截取 ISO 字符串；采购单 `PO20260902021` 原先被截断显示为 `2026-09-02T13:05`，现按北京时间显示 `2026-09-02 21:05`。本次只修改两页创建时间列，预计到货日期、对账期间和业务数据保持原逻辑。
- 货架页面按 `isElectronRuntime()` 判断实际桌面运行时，不能用浏览器生产构建也启用的 `VITE_ELECTRON` 标识判断。浏览器显示“浏览器可提交打印任务。如需使用本机标签打印机，请打开极序 Flow 桌面客户端。”
- 桌面接口存在、打印方法不可用时显示简短重启及联系管理员提示，不在业务页面要求用户执行控制台命令或排查预加载脚本。
- 打印机管理也按运行时和实际枚举能力分支：浏览器引导使用桌面客户端添加；桌面枚举不可用时提示重新打开；可用时显示与现有「添加打印机」按钮一致的说明，不再向浏览器显示本机操作指引。
- 同一打印工具文件的入队请求头也使用实际运行时判断：普通浏览器不声明桌面本机打印来源；真正桌面端仍保留本机来源和已注册客户端 ID。业务页面继续只入队，物理打印仍由既有桌面轮询客户端执行。
- 条码打印查询接入共用 `DataTable` 虚拟化，达到 200 行时使用工作区滚动容器和真实行高测量。API 仍加载完整结果，筛选、总数、状态汇总、3 秒刷新和逐行补打保持原逻辑。此前未显式开启虚拟化，主任务实测 5,707 行、main 下 190,740 个节点，导致页面读取超限和交互超时；修复只限制挂载行数，不把多行商品/打印结果单元格改成固定高度。
- 操作日志同样接入现有虚拟化；主任务修复前实测 13,428 行、main 下 282,057 个节点和关闭工作区标签超时。保留全量数据、筛选及详情入口；不修改全局 `DataTable` 默认开关。
- 条码打印查询仅在显式且合法的正整数 `inboundTaskId` 入口显示当前收货链路，失败、超时和排队/打印中计数仅统计该收货单。普通全量页面不再把首条记录的收货单当成当前上下文；非法 ID 不生成链路入口。无效明细 ID 同样复用现有正整数参数解析。
