# 系统 UI 一致性检查：以销售订单为基准

## 本轮现场和边界

2026-11-12 在 Safari 普通窗口，通过真实鼠标、键盘操作修复工作树 `codex/gui-remediation` 的本地预览；测试库是上轮专属合成 MySQL，页面标题和角标显示“隔离测试 · 非正式”。没有对正式库、真实客户或真实打印设备操作。检查为 UI 审查，未修改业务代码。

本轮在电脑操作记录中实际观察了屏幕截图；当前工具没有将截图保存为独立图片文件，故下面的位置和操作步骤可用于重新复现，但没有提供可离线查看的截图文件。尚未完成全页面、所有岗位、窄窗口、屏幕阅读器、PDA 真机、Windows 客户端及实体打印检查。

## 1. 销售订单基准：实际操作与可沿用的规则

1. 从待办中心点击“销售订单”。列表以页面标题及一句用途说明开头，右侧是导出、查询和新建；下方为状态分类、已应用条件、数据表及总数。单号查询 `SL20261112002` 后，筛选条件和 1 条结果均可见。
2. 点击“查询”：弹窗有标题、说明、分组、字段标签、底部重置/取消/查询；打开后焦点在单号输入框。
3. 点击“新建销售”：独立工作区页以“订单信息”“商品明细”分组；空草稿点击保存后同时提示客户、仓库和商品缺失，焦点回到客户入口。取消返回列表。
4. 打开筛选结果的“查看”：详情页展示单号、状态、核心摘要、订单信息/发货安排/作业进度等分区；切换“作业进度”显示当前仓库任务和下一步。操作列需要先横向滚动才看到，详见问题 1。

以上是本次实见的基准，并非要求所有页面机械复制销售字段或业务动作。销售页自己的横向可见性和日期范围展示也需要完善。

## 2. 应统一的系统 UI 规则（建议）

| 场景 | 建议采用的规则 |
|---|---|
| 页面头部 | 名称与导航、工作区标签一致；标题下用一句话说明用途。右上按“辅助操作、查询、主要动作”排列；没有安全主动作的页面不强加新建按钮。 |
| 列表和状态 | 优先展示单据身份、对象、关键数量或金额、状态和下一步；操作应在常用窗口宽度中可发现。状态用文字配合颜色，不仅依赖颜色。 |
| 查询 | 延续销售的分组、清楚字段名、重置/取消/查询及默认焦点；默认时间范围也应在结果页可见。明确“重置为默认”与“清除全部”是不同操作。 |
| 表格 | 单号、日期和金额优先保证完整可读；文本需要换行时避免在编号、日期中间断开。内容过宽时提供可见的横向滚动提示，必要时固定身份与操作列。 |
| 表单 | 信息与明细分组，必填明确；失败在相关字段附近给出原因并保留输入。保存、取消和返回的含义应稳定，离开有未保存输入时提示。 |
| 详情 | 以销售的单号、状态、摘要和分区为参考；危险动作与常用动作分明，状态、下一步与原单可追溯。保留从列表进入时的筛选及返回位置。 |
| 空、加载和失败 | 区分正在加载、真实零结果和读取失败；空态告诉用户是无数据还是筛选无结果，并提供可用的下一步。 |
| 无障碍 | 图标按钮有可读名称，焦点可见且弹窗关闭后回到入口；键盘操作、对比度和不同缩放要单独实测，不能仅凭截图认定达标。 |

## 3. 本轮发现

| 优先级 | 页面与步骤 | 现象和影响 | 建议 |
|---|---|---|---|
| 高 | 销售列表、采购列表、库存总览 | 当前普通窗口中销售表的创建时间和操作列位于可视区域右侧；采购“详情”按钮靠右部分被裁，库存的在库/预占/可用数量位于右侧。点击销售操作单元格后表格确实横向移到右侧，但初始画面缺少明显提示；此时左侧单号又移出视野。 | 给表格明显的横向滚动提示；评估固定关键身份和操作列、压缩低优先级列；在同样窗口下验证鼠标、触控板和键盘。 |
| 中 | 销售、采购默认列表与报销列表 | 销售和采购默认查询使用 11 月 6–12 日，但列表初始未见日期条件；报销则直接显示当天日期条件。用户容易把默认时间范围内的结果当作全部历史。 | 把有效时间范围统一显示在列表上，并允许清楚调整；是否默认一周或一天仍按各业务现有口径。 |
| 中 | 费用报销查询 | 点击“清空”后创建日期仍回到当天。与销售/采购弹窗“重置”的文字和行为存在歧义，用户可能误以为已无日期限制。 | 使用“重置”并说明恢复默认；若需要不限制日期，应单独提供明确动作，并验证实际查询。 |
| 中 | 费用报销列表 | 普通窗口创建日期 `2026-11-12` 显示为两行；审批人长名称也换行，增加扫读负担。 | 日期列预留宽度并禁止日期内部换行，长名称按明确规则完整展示或提供可访问的完整内容。 |
| 中 | 批次拣货空列表 | 空态只显示“暂无数据”，页面没有说明是尚无批次、筛选无结果，还是应从哪里开始。 | 根据实际空态分别说明，并在有权限、真实可执行时给出下一步入口；不虚构新建能力。 |
| 低 | 销售/采购/报销查询 | 销售和采购采用分组、左侧“重置”的页脚；报销弹窗为紧凑单区、“清空”靠右。功能相关但视觉和动作名称不一致。 | 统一页脚位置、术语和字段间距，保留各模块必要字段和默认条件。 |
| 低 | 用户管理与订单列表 | 用户管理采用页内搜索栏，销售/采购采用查询弹窗；两者使用场景不同，但入口位置与“搜索/查询”术语不一致。 | 为简单关键词搜索和多条件查询各定义一种明确模式；不要为统一而增加多余点击。 |
| 中 | 销售详情顶部 | 已打开的拣货中销售单同时排列“发起退货、按这张单再开、取消订单、打印订单、修改订单”五个同层按钮；取消虽用红色，但夹在常用操作之间，页面没有突出当前状态下最常做的下一步。 | 结合岗位和状态确定最常用动作，保留必要入口并将低频操作收纳；危险操作保持明确确认，不改变现有权限和状态规则。 |
| 低 | 销售详情作业进度 | “待分配分拣格”说明中直接嵌入按钮，按钮与前后文字连在一起，扫读时不容易分清问题、操作和操作后提示。 | 将原因、动作和后续说明分开排列，沿用现有“去分配分拣格”功能，不暗示分配本身已完成。 |
| 中 | 库存管理头部 | 查询、导出、导入库存、出库、查看盘点五个按钮视觉权重接近；其中涉及数据写入的入口与只读导航挤在一排。 | 按用户任务区分查看、导入和业务写入；在不隐藏必要权限与安全提示的前提下减少头部并列操作。 |
| 低 | 销售详情摘要 | 示例中摘要为两列网格，回款状态单独占据下方一行，留出较大空白；同一状态在基础信息又出现一次。 | 保留业务必需的信息，调整布局和重复展示，让订单身份、金额和履约状态更易扫读；不同屏宽分别验证。 |

## 4. 已覆盖与后续

实际查看：登录、待办入口、销售列表/查询/空表单校验/详情和作业进度、采购列表与查询、库存总览、费用报销列表与查询、批次拣货空态、用户管理、成本对账。其他页面、跨岗位交接、失败注入和窄屏尚未检查；本报告不是全系统功能或无障碍通过证明。

下一轮应按同一基准补采购新建与详情、收货、销售退货、盘点、客户和供应商往来、凭证与报表、打印设置及 PDA 浏览器流程；然后逐项保存可复核截图、核对权限角色、窄窗口及实际设备，再根据确认的问题形成独立整改计划。
