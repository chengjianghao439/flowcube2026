# 本轮设计基准与合理差异

日期：2026-10-08。本轮遵循 impeccable 的 product / critique / audit / extract / clarify / adapt / harden / polish 方法：A/B 先独立提出问题，再用真实隔离页面证据对照；主代理集中收口公共组件和变量，各模块保留业务语义。方法应用和反例见 assessment-a.md、assessment-b.md、专项测试及浏览器记录。

## 现有基础

极序 Flow 已有克制的蓝色品牌、中性工作区、PageHeader、DataTable、AppDialog、Finder、OrderDetailSections、QueryErrorState、状态生成常量和恢复平台。销售列表的读状态、单据详情的信息分组、原回执核对和完整商品身份是本次采用的较成熟模式。重构沿用它们；单页特殊布局继续在所属页面表达。

## 同语义的共同规则

| 场景 | 统一基准 | 本轮实现与核验位置 |
| --- | --- | --- |
| 列表 | 标题和主行动固定在 PageHeader；真实空结果与读取失败分开；失败可重试，计数和金额不伪装成零；不让旧列表成为新鲜可写来源 | BaseCrudPage、采购/退货/客户/退款、PaymentsView、资金流水、凭证及 PDA readFailure |
| 身份与密度 | 编码、名称、供应商型号、型号、颜色完整显示；金额右对齐；只有明确指定的辅助备注可展开折叠，双击备注不打开单据 | DataTable expandableText、原商品身份组件、供应商退款来源表；textWrapping 反向守卫 |
| 表单 | 可见标签对应具体控件；新建与编辑有明确身份；实际 write 权限决定入口；提交期间全部关闭通道及输入锁定；失败保留输入，隐藏页原成功回执等待人工核对 | BaseCrudPage、八个调用方、客户退款、资金账户、销售表头 |
| 详情 | 先单号、对象、业务阶段及关键金额，再原单和明细；资金事实、审批状态、凭证结果分别呈现 | 两侧退款详情、现有 OrderDetailSections；供应商名称取准确原单快照 |
| 浮层 | 使用既有 Dialog / AppDialog；标题可读，内部滚动和操作区可达；有焦点边界；PDA 浮层开启时同步暂停键盘与原生扫码 | ERP 既有浮层；PdaDialog、超收及更新提示 |
| 选择器 | 名称、查询、选中、确认、取消有明确语义；长身份不截断；选择与最终确认继续沿原调用合同；键盘移动焦点不会自动写业务 | FinderTable、PickerField、WarehouseSelect、原 owner / 活动代次守卫 |
| 反馈 | busy、明确失败、已完成和结果待确认不同；待确认只查询准确原请求，原键原体重试资格保持；重要错误持续可读 | 既有恢复平台、供应商退款来源显示快照、PdaFlash / Scanner |
| 颜色 | 状态文字使用 semantic ink；动作背景保持原品牌和语义；success 表示完成、warning 待处理/注意、danger 阻断或危险，单据阶段不代替资金/审批结果 | index.css、tailwind、statusTone；明暗背景实际对比度计算 |
| 工作区 | 当前标签与焦点可识别；方向/Home/End 移焦，Enter/Space 激活；独立关闭按钮；关闭脏草稿先确认，取消保留输入；KeepAlive 的读取与写回边界保持 | WorkspaceTabs、BaseCrudPage、原 store / dirtyGuard |

## 应保留的差异

- ERP 是密集数据和多标签工具；PDA 是扫码任务与至少44px触控区，不使用同一个页面布局。
- 销售涉及预占、客户价和回款，采购涉及实际到货和供应商结算；两侧阶段与下一步动作不能同名硬合并。
- 客户退款是资金支出；供应商退款是准确采购退货与原付款分配的资金收入，确认冻结和实际到账分步。库存退货与退款独立。
- 供应商退款四位金额、普通资金两位展示、会计借贷无货币符号、合法数量最多两位、真实箱数/百分比整数分别沿用原合同。
- 客户编码独立列、授信/价格等级和供应商提前期各有作用，不能为了列形相同删掉。
- 供应商退款保留已授权的有界分页合同；本轮没有后端关键词/日期筛选合同，不做前端仅筛当前页的假搜索。后续若统一完整结果搜索，需先设计读上限、过滤与归属生命周期。
- 缺历史名称/型号时明确缺资料；不查当前主档或按名称猜原关联。账户等缺人类名称的原身份保留准确 ID 和“原账户”含义。
- Android 实体扫码、相机、软键盘、打印和银行实际资金事实需对应现场验收；浏览器和测试不替代这些证据。

## 视觉验收边界

基线与 after 的代表截图使用本批真实 API 与专属临时 MySQL 的同一合成资料。每张记录自己的尺寸、主题和具体状态。全路由入口总览、详细看图、限定交互、组件测试、数据库读写、真机和生产是独立证据。`.dark` 仅为浏览器 DOM 模拟，因为本次没有确认可操作的产品主题开关；不能宣称已验收用户主题切换。中途 HMR 的全页 reload 会丢浏览器内存中的 PDA 绑定，需重新正常绑定后继续，不计为 SPA 自行丢绑定。
