# 本地开发页面切换卡顿

## 本次定位

2026-09-09 在本机 Node/Vite 开发模式、已登录的 Chrome 中检查。基础健康请求为 3–5ms；商品页包含 2,636 行、约 93,807 个 DOM 节点。切换到快递账号页时记录到约 700ms 的主线程长任务。该采样含浏览器自动化开销，不能当作所有用户的固定耗时。

“需要关注”的低库存计数误用完整列表读取，顺序拉取 39 个批次，约 4 秒；总数首批已经返回。低库存独立卡片原有的 20 项摘要与此不同。

## 现行规则

- 低库存风险计数使用 `getLowStockPageApi(1, 'summary')`，只读取一个有界批次及服务端总数，缓存键与完整明细分开。用户打开风险明细时仍按原规则读取全部记录。
- `TableActionsMenu` 在首次展开前只渲染普通按钮；点击、Enter/Space 原生按钮激活、ArrowDown 都可以初始化并展开菜单。主操作始终直接可用。
- 首次展开后保留菜单实例，继续使用 Radix 的键盘、焦点及页面隐藏规则，切回页面保留打开状态。禁用行不能展开。
- 商品表格及其列定义按真实依赖缓存；无关工作区路由变化不重绘全部商品行。导航事件使用最近已提交的 Router 导航函数；分类、商品数据和打印中状态变化仍更新表格。
- 不删除开发数据，不改变列表数据范围、导出、业务权限、列宽或列顺序；本次不引入虚拟滚动，全部行仍在 DOM 中。

## 验证

- 新增 `dashboard.test.ts`：通过真实请求客户端和离线 Axios adapter 验证摘要仅请求一次、完整明细仍聚合全部批次。
- 新增 `TableActionsMenu.test.tsx`：验证闲置菜单不挂载、主操作、首次展开、禁用、键盘和隐藏后的状态保留。
- 新增 `products/index.performance.test.tsx`：使用真实商品页面与 Router，验证切换其他菜单不会重新渲染未变化的商品表格。
- 修复前菜单预挂载、计数全量请求及商品表格重绘断言均失败；最终 6 个相关测试文件、28 项测试通过（单 worker），`tsc -p tsconfig.app.json --noEmit` 与 7 个受影响 TS/TSX 文件的 ESLint 通过，`git diff --check` 通过。
- 已登录 Chrome 实测：风险计数请求只有 `page=1&pageSize=10` 一批（191ms），另有独立卡片的非分页摘要请求（73ms）；不再自动续到第 39 批。完整明细聚合由 adapter 回归覆盖，本次未打开数千行风险明细。
- 商品页保持 2,636 行；未展开的行不再生成 Radix Trigger。鼠标首次展开显示原菜单项，首次 ArrowDown 聚焦“打印标签”，Escape 关闭并聚焦“更多操作”。切换后点击首行“编辑”进入正确商品编辑页；未改字段、未保存，随后关闭临时编辑页。
- `TableActionsMenu` 单测保留真实 Root/Trigger 与可见性 hook，替代无布局 jsdom 中的浮层内容；真实 Portal 定位、键盘首项和焦点归还由上述 Chrome 检查覆盖。
- 性能口径：简单点击后两帧的 28ms/78ms 只反映早期响应，不能当作整页显示完成。进一步以目标面板实际显示再等待两帧的采样，商品→快递账号约 477–695ms，返回商品约 1,464ms。浏览器调试与自动化仍有开销，未取得同口径修复前对照，不能给出准确提速百分比。大列表仍有明显 DOM 布局成本，本次未完全消除。
