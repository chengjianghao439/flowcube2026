# 仪表盘与销售订单页面重构

用户已确认第二版视觉稿，现接入本地项目真实数据。新增销售只读汇总和应收到期分布，不改变库存写入、订单状态机或权限规则；本轮实现纳入 v0.9.5 发布；以下本地验收记录不代表发布状态，实际发布结果以同 SHA 的 CI 和线上验证为准。

## 仪表盘

- 页面定位从静态“数据总览”调整为经营工作台，优先回答“今天需要关注什么”。
- 业务待办按订单状态进入列表；从首页进入销售列表携带 `range=all`，计数和结果均为全部日期。风险面板内提供有权限的新建销售单、采购单入口。
- 默认四项摘要为待处理销售（状态 1/2/6）、今日出库、未清应收、待我审批。下方为业务待办、需要关注、月度销售趋势、应收到期分布；移除在库 SKU 数注册项，趣味组件和版本不默认展示。风险与审批按权限挂载。
- 阅读态不再使用一整面自由卡片墙，按“今日重点、待办与风险、业务走势、我的组件”分区；四项指标固定为紧凑首行，待办和趋势使用稳定的双栏阅读节奏。
- 保留布局编辑、组件库、拖拽和宽度调整。仍同时显示木鱼、下班和假期倒计时的旧布局自动迁移到新默认，之后仍可从组件库按需加回；上一版默认可见组件顺序、宽度完全一致的布局也迁移；其余个性化布局继续保留。
- 指标卡改为先读名称与数值、再读说明和趋势的结构，分区进入时使用轻微淡入上移动效，并遵循系统减少动态效果设置。
- 低库存列表允许真实数据中出现同商品同仓库的重复投影记录，每一行使用独立渲染标识，避免 React 复用错误。

## 销售订单

- 状态标签返回符合其他筛选条件的全量状态计数，不受当前页或当前状态限制；列表数量来自后端批量只读投影，按基本单位分别合计。
- 关注项优先展示取消待归还、改单待归还、授信待审批等事实；尚未占用不等于缺货，只有 ATP 查询能够判断是否不足。
- 点击单号打开按需加载的右侧预览，显示商品编码、供应商型号、型号、颜色、数量和全部仓库任务，保留列表位置；支持关闭、完整详情和已有占库入口。
- 紧凑/舒适密度使用本机存储；列表和预览加载失败显示可重试错误状态。
- 默认日期为北京今天及前六天；从仪表盘携带 `range=all` 时不添加日期限制。

- 新建、编辑、执行期改单与详情页进一步收紧首屏纵向间距；订单信息字段统一为紧凑高度，详情基础信息在宽屏改为两行排列，使商品明细在常见桌面窗口中直接可见。
- 占用库存升级为销售订单专用宽弹窗：每条明细固定展示名称、编码、供应商型号、型号、颜色、单位，集中显示需求、已占、待占、本次占用、当前可用、预计到货及占后剩余，便于识别同名不同规格商品并判断库存缺口。

- 页面标题统一为“销售订单”，说明覆盖下单、占库和出库主链路。
- 增加全部、待占库、部分占库、已占库、执行中、已出库快捷筛选；仍使用原 URL `status` 参数和服务端查询。
- 增加销售单号快速搜索、刷新、高级查询、日期范围与服务端订单总数摘要。
- 状态入口使用低干扰的分段选择器，当前状态用轻量描边与阴影确认；搜索、日期、订单总数和高级查询集中在同一区域。
- 保留原有导出、筛选标签、表格列宽记忆、分页、订单操作、打印及确认流程。
- 通用页头在窄屏改为上下布局，避免标题与操作按钮互相挤压。
- 新建、草稿编辑和执行期改单统一“订单信息、商品明细、订单汇总”结构；客户履约与收货信息分组，金额、折扣、商品种数、数量和低于进价提示使用同一汇总组件。
- 详情页增加客户、仓库、商品种数、订单金额和回款状态摘要，详情选项卡增加图标并支持窄屏横向浏览；基础信息改为响应式网格。
- 占库、取消占库、发货、缺货、高级查询和地址簿弹窗统一说明文字、表格表面、行反馈与操作层级；地址簿在窄屏显示可操作按钮。
- 占库弹窗把实物、已占、预计到货和可承诺量分开展示，库存不足时禁止确认；发货弹窗支持按明细输入本批小数数量并展示编码、供应商型号、型号、颜色和仓库。
- 列表中的发货与取消占库改为进入详情核对，避免从行菜单直接执行库存动作；取消和删除请求加入稳定请求键。
- 销售保存由服务端重新读取启用中的客户、仓库、商品和承运商生成快照；折扣、授信、部分结案应收、分仓扫码归属及逐仓权限使用统一后端口径。
- 仪表盘授信预警同步采用折后净额并纳入部分占库订单；待处理销售统计也包含部分占库，避免此状态从首页待办中消失。
- 销售完整性复审补齐取消、改单、授信和精度边界：销售仓库任务只能从订单统一取消，改单不得让原折扣超过新货款，授信审批按快照限额复用，资源写操作幂等绑定订单 ID，数量最多保留 4 位小数且折算后不能为零。
- 收货人或部门、座机和国际联系电话放宽至 30 字符，详细地址保持 200 字符；迁移 `233_expand_customer_address_contacts.sql` 同步地址簿字段。

## 验证边界

已执行两端 ESLint、前端 TypeScript、71 项前端单测、13 项销售契约测试、生产构建和 diff 空白检查。临时独立库 `flowcube_sale_test` 完成 233 个迁移，销售改单 61 项、并发与取消归还 87 项、ATP 8 项均通过；本机开发库另行执行并核验了迁移 233。自动化浏览器可连接本地 Vite 且控制台无应用错误，但隔离会话停在登录页，未使用账号绕过鉴权；真实销售数据下的桌面与窄屏交互仍需复用用户登录会话验收。

## 真实数据接入后的六项优化

- 销售趋势改为订单金额 / 已出库订单金额 / 订单数切换。原折线是金额，并非数量；图表注明单位及按订单创建月份归集，不把已出库整单金额解释为分批出库流水金额。
- 业务待办默认优先显示 5 单：待实物归还、授信待审批、创建最早；支持预览和查看全量。`focus=pending` 遵循销售仓库范围，导出同步此筛选，并订正旧导出状态文字。
- 低库存旧无 page 接口仍返回最多 20 条；带 page 返回完整分页总数，按商品/仓库汇总后筛选实物量 ≤ 10。授信预警带 page 返回超限客户分页，旧 top 接口保持兼容。两类风险都能打开专用明细，库存跳转带商品编码和仓库，授信跳转带客户与全部日期。
- 普通执行/完成订单的关注列留空，异常、未占量、待归还和待审批继续显示，避免重复履约状态。
- 未生成应收统一使用中性说明；存在账款后才显示付款和逾期状态，列表、详情和预览共用逻辑。
- 销售预览提供当前页上一单/下一单，首尾禁用越界，切换时复位内容滚动；列表高亮当前预览订单。仪表盘待办也复用同一预览。
