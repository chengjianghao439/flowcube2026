# 采购计划与补货建议的供给净额

2026-09-06 工作区实现；没有提交或发布。两个视图保留现有采购建议合并页，原路径保持：采购计划生成可编辑计划，再按供应商与仓库转采购单草稿；补货建议生成采购申请草稿，人工核对、提交审批后转采购单。

## 需求与库存口径

- 商品×仓库驱动集包含库存维度、ACTIVE 容器、启用补货策略、近期销售出库和未发销售行。没有历史出库、没有库存行的新品，只要有未发销售也可进入建议。
- 未发销售按行 `quantity - shipped_qty`（非负），包含销售状态 1、2、3、6，排除已出库和已取消；行仓库优先，旧行回落单头仓库。页面明确包含未占库订单并单列其中销售草稿量。
- `containerEngine.getStockProjections(conn,pairs)` 为共用批量 ACTIVE 实时投影入口，读取 `inventory_containers.remaining_qty`；缓存 quantity 不参与采购净额。有效预占来自受控库存投影，作为需求保护下限。
- 预计采购直接复用 `expectedStock.getExpectedStock()`，采购状态 2、5 的逐行未上架总量；作废收货不抵扣，预计绑定单独展示，不再减一次。新增 `supplyItems` 提供全部未上架供应的数量与日期，原 `items` 仍保持可绑定剩余量语义。
- 采购计划历史预测沿用 SMA/WMA。WMA 最近半窗权重 2、其余权重 1，分母为实际加权天数，修正奇数窗口归一化。
- `剩余预测 = max(0, 预测量 - 未发销售)`；`总需求 = max(预测量, 未发销售, 有效预占)`，避免销售与预测相加及预占/预计绑定重复扣减。
- 计划净需求为 `max(0, 总需求 + 安全库存 - ACTIVE实物 - 预计采购 - 暂定覆盖)`。补货建议使用相同净额，但缓冲取目标库存（目标已经包含安全库存，不能再加安全库存）。补货点或未发销售缺口触发补货，原手工补货点语义保留。
- 所有数量使用基本单位，按万分之一精度舍入。只读建议与生成/转换事务复用同一公式。

## 包装与起订

迁移 `236_procurement_supply_planning.sql` 增加供应商×商品的采购包装规则、采购规划互斥行和计划供给 JSON 快照。

采购计划管理员可在两个视图的“需求与覆盖”中维护采购单位、整包装倍数、最低起订量；单位选择复用商品已有 `product_units`，服务端复用 `resolveConversionRate` 解析权威换算。规则按录入单位保存，净额与采购建议折算成基本单位。0 表示不限。

建议量为 `ceil(max(净需求, 起订量) / 包装倍数) × 包装倍数`，净需求为 0 时不因 MOQ 新增采购。净需求 73、包装 12、起订 100 得到 108，多购 35。页面分别展示净需求、采购建议与多购量。转换时再次按当前供应商规则校验；切换计划供应商会按新规则调整尚未转换数量，已有历史快照保留。

接口为 `GET/PUT /procurement/purchase-policy`，沿用采购计划管理权限。数据有明确产品/供应商校验，不新增权限常量。

## 覆盖、防重与释放

暂定覆盖分开显示：

1. 采购计划头处于草稿/部分转采购，行仍待处理的 `adjusted_qty`。
2. 采购申请草稿、待审批、已批准的 `quantity - converted_qty`。
3. 未删除采购单草稿的明细数量。

已转计划行退出计划覆盖；已转申请部分退出申请覆盖，下游采购草稿/预计采购仅计一次。取消、忽略、拒绝、减量或删除后，查询直接按当前单据状态和数量释放相应覆盖，不维护另一份库存账。已转换上游取消不影响下游单据。

采购计划和请购事务在单据锁前先锁 `procurement_planning_lock.id=1`，生成、编辑、转换统一重读当前覆盖。不同请求键、不同计划和两个建议入口也不能重复生成同一剩余缺口。计划本行、正在校验的请购单从当前计算排除自己的覆盖，其他单据照常计入。转换时数量超过最新包装建议返回 409，需减量或忽略；同一请购明细重复转换请求行直接拒绝。已有生成/转换入口携带稳定请求键，转换 action 绑定单据 ID。

手工请购是独立业务申请，保留人工新增需求能力；它的未转换量参与建议覆盖，但不被“补货建议来源”的自动缺口上限限制。手工采购单、销售需求、收货等仍由原业务事务管理；采购规划锁串行计划/请购写入，不锁住整个仓库，也不承诺人工独立采购与自动建议永远无并发差异。转换时再次核对当前状态和数量。

## 到货与跨仓候选

总量净额会抵扣既有预计采购，但不宣称已经按期覆盖。页面列出未上架采购的预计到货日（含待确认）、最早未发销售交期，以及晚于最早交期的供应量；未知日期保留待确认。销售交期读取迁移 235 的行覆盖/单头默认。需求与覆盖只返回权限内仓库的汇总，不输出客户订单明细。

调拨来源只在用户授权仓库范围内选取 ACTIVE 实物余量，先保护来源仓未发销售、有效预占、预测及目标/安全库存，不使用来源仓未来采购作为可调拨实物。每个候选显示数量与“出库、运输、上架时间需人工确认”的条件。候选不抵扣采购量，也不自动创建或确认调拨单。

“核对调拨单”将来源仓、目标仓和建议明细带入现有新建表单。已有新建标签中有表单时显示“带入采购建议 / 保留当前表单”，明确提示替换当前未保存内容，避免静默覆盖。用户仍需核对数量、时间并保存/确认，实际可出库由原调拨业务校验。
