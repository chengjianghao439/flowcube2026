# 应用部署与运维边界

网页和 PDA 的现行入口见 [GitHub 手动离线应用发版](manual-release.md)。本次仅代码候选，服务器配置与启用须由运维另行审批，不能把文档写完当作已上线。

- 合并/push 不发版；老大完成可核验的“发 + 完整 SHA”批准后，亲自在 main 手动触发。
- GitHub 标准 runner 构建并经受限 SSH 直接交付；服务器不更新 Git、不安装 npm 依赖、不 docker pull，不依赖 Mac。
- 保留服务器实际 Compose 文件顺序组合和现行数据库版本锁文件。仅追加两应用的临时 image override，文件内容与用途列入运维审批清单。
- 只执行目标镜像代码自带迁移；数据库引擎升级、参数、cron、权限变更由运维单独申请。现有 MySQL 缺失或不健康就停，不自动启动/修复。
- 失败立即停止，无自动回滚。运维核对本次备份收据，按照已批准的备份恢复方案处理；不恢复不兼容旧后端写入。
- 自动 smoke 不代替运维检查、正式系统真浏览器人工 QA 或 Windows/PDA 真机验收。

旧 `release:prod`、`complete-release` 与 Mac relay CLI 已明确拒绝执行。不要使用历史记录里的 Git 更新、任意 root SSH、skip gate 或自动回滚命令作为应用发布入口。桌面 EXE 的独立 Windows 构建及下载目录契约保留，见 [RELEASE](RELEASE.md)；它不会触发网页/PDA发布。

运维启用所需的账号、新钥匙、指纹、sudoers/强制命令、OIDC 公钥信任、GitHub环境/Secrets、实际路径清单、演练、旧key另批停用及写入保留责任，统一见 [手动发版运行手册](manual-release.md)。本次不执行这些步骤。

## 发布成功后的镜像与磁盘收尾

每次正式发版成功且本地、公网健康及版本验收通过后，必须完成镜像与磁盘盘点，在该版本发布结果中记录保留集合、拟清理清单及处理结论。此项是发布成功后的运维收尾；发布期间和失败恢复阶段仍遵守原门禁，不因空间不足自动清除镜像。

1. **先只读盘点并保存脱敏证据**：核对服务器身份、发布 SHA、当前实际镜像 ID、标签/OCI revision/digest，以及全部运行中和停止容器的镜像引用；记录磁盘使用和可用空间。镜像名义总大小含共享层，必须与实际可释放量、清理后实测空间净增分别记录，不能相互替代；慢盘诊断仍使用有时限、按目标的查询，不做无界全盘统计。
2. **按真实用途保留**：保护当前运行版本、数据库和发布门禁必需镜像，以及经过验证与当前数据结构和业务写入契约兼容的必要恢复版本。保留镜像不等于可安全回退；不能把旧版本、可空 DDL 或迁移记录单独当成恢复写入的兼容证明。没有经验证兼容的恢复版本时，明确记录并按上节向前恢复要求处理。本规则不设固定保留版本数量。
3. **核实恢复来源和相同副本**：恢复证据可以是仍可获取、完整性已验证的同 digest 仓库副本，或能还原完全相同镜像 ID 的既有 CI 归档/可靠备份。仅有 tag、源码可重建、来源报告或过期归档不算恢复证明；缺少 RepoDigests 本身也不等于不可恢复。删除前核对归档实际可获取性、完整性和目标镜像身份，不输出凭据。
4. **只提出明确无引用、无必要用途的旧镜像精确清单**：逐项列出完整镜像 ID、标签/身份、大小、全部容器引用核对结果、恢复证据和删除风险。已确认不能恢复、可能唯一副本或尚不能证明可恢复的对象，必须先取得用户针对此清单的永久删除确认；没有确认就保留并记录待确认。恢复用途或身份不明的对象先核实，不为释放空间扩大清理范围；发版成功本身不构成删除授权。
5. **在已授权范围内低 IO 执行并复核**：执行前再次检查引用、保留用途、部署状态及 IO，沿用 [AGENTS.md](../AGENTS.md) §0.1 和[云盘清理约束](deploy-disk-precheck-2026-09-19.md)的分批上限、低优先级、批间等待要求，健康或 IO 异常时暂停。一次性批量例外不改变后续默认规则。使用精确镜像 ID 正常删除，不用宽泛 prune 或强制删除，不为通过镜像删除而删除容器。镜像清理不包含任何容器、数据卷、数据库、备份、业务文件、日志或远端仓库产物的删除，也不包含服务重启或重新部署。
6. **收尾必须有结论**：记录每项成功、失败、跳过或结果不明，实际空间净增和最终余量，并核对原容器 ID、启动时间、重启次数、挂载，以及本地/公网健康和三端版本。客户端超时不能视为删除成功，须检查实际状态后再决定下一步；没有可安全清理对象或仍待确认也应如实记录；不得借镜像清理擅自缩短备份保留期或改变已约定的镜像保留用途。


## 资源、备份和受限账号

接收器保留 global flock、最多4GiB整包与8GiB镜像展开上限（实际策略可更小）、6GiB空间保留、10400秒整次接收/执行上限；发送端10800秒，网页发布job215分钟。固定执行器保留1800秒镜像加载、300秒新鲜备份/收据联合窗口、300秒迁移和浏览器资源/超时限制，程序不prune任何旧镜像/备份。所有实际路径和容量先列入运维审批，不能靠加大内层超时掩盖外层强杀。

备份helper在停写后创建全新0700目录与0600快照/收据，绑定目标SHA、实际MySQL容器/镜像/UUID/版本/库/迁移前记录，并独立复算快照大小与摘要。旧cron备份不能替代；失败不迁移。收据固定 `restorationVerified:false`，不声称恢复演练成功。运维必须在批准前另行完成实际备份与可恢复性确认。

完整及受限smoke账号由运维放在策略指定的root-owned私有环境文件，两组缺一即停。浏览器镜像及锁定运行时事先准备，发版时从已核CI后端镜像复制运行时，不在线安装。受限账号长期保留按原权限制度管理；不在代码/日志/报告记录口令。
