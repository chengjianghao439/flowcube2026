## 已修复的问题

| 问题 | 实际影响与处理 |
|---|---|
| 三位及更多小数可以绕过数量限制 | 旧后端只区分整数/非整数，前端只改 step；`.005` 拆分会因两侧分别舍入增加 `.01` 库存。现对原始数量先拒绝超两位，再执行计算与写入。 |
| 单位折算先取整后验证 | 原数量 `1.004` 可被改成 `1`，金额仍按原数量计算。录入数量和未取整的基本单位结果现在都检查精度；不静默改量。 |
| 逐箱约束被合计绕过 | 整数商品的 `.5 + .5` 曾可收货/盘点；现逐箱、逐扫描行检查，退货合格与不合格量分别检查。盘点同时移除逐容器重复查询，改一次批量写入。 |
| 执行和配置入口漏校验 | 补齐释放占库、退货收货/质检、拣货、装箱增减、手工收货计划、拆分与归还，以及采购计划、包装倍数/MOQ、安全库存/补货点/目标库存。 |
| 合法小数运算产生假超量与错误状态 | `.3-.1` 和 `.1+.2` 可能导致拒绝拣货/退货，扣空条码仍 ACTIVE，整箱归还误拆换码。现先验证原量，随后按百分位计算差额、分配、余量和状态。 |
| 商品小数开关无法保存 | 请求 schema 缺字段，Zod 剥掉 `allowDecimalQty`。现严格接收布尔值；省略字段保留旧客户端语义。 |
| 数量策略权限和缓存失效 | 作业账号原来需要完整商品查看权限；超过 500 商品可能漏查，空 ID 变成 0，保存开关后缓存未刷新。现最小只读权限、正整数筛选、500 条分批，随商品保存失效。 |
| 前端数量与组件回归 | 24 处数量框显式检查输入/粘贴/失焦，提交草稿也校验；修复数量显示和派生计算残留四位、采购 `1e2` 被截为 1、禁用选择器仍能清除。 |
| 工作区标签更新丢失 | 缓存命中时子组件更新早于父标签注册，单号丢失；旧列表名也被当成自定义单号保留。已分别修复并加真实 effect 顺序与 store 回归。 |
| 守卫“全绿”是假覆盖 | 旧数量守卫只检查导入，删除真正调用仍绿；文案正则会误剔 URL 并漏掉模板/双引号/JSX。现 AST 检查实际调用与文案，删除/改名/注释伪装的反向验证会失败，补齐漏网文案。 |
| 部署与正式发布链不可靠 | 修复分片内外超时不一致、远端清理续行被注释截断、PDA 提前退出等待；增加有摘要校验的 HTTPS 拉取及独立 SCP 回退、持续浏览器进程冒烟、同 SHA 发布编排、真实安装包下载摘要验证。详见 [发布流程修复](release-flow-speed-2026-09-22.md)。 |

数量规则：超过两位有效小数返回 `QTY_DECIMALS_EXCEEDED`；整数商品还返回 `QTY_INTEGER_REQUIRED`。`1.230` 尾零可接受，合法机器浮点噪声可接受。采购单和 PDA 拆分原有更严格的整数录入规则保留。**金额、单价、授信和换算率精度保持原规则**，不套用数量限制；此前执行的迁移不改写。
