## 优先处理建议

1. **避免用户误读结果或误操作。** 销售、采购、库存流水及物流列表的默认日期不明显；销售手输倒置日期、商品价格上下限倒置仍执行查询；已有采购退货原单载入时默认为全部剩余可退数量；已抵扣发票提供后端禁止的删除入口和可能误导的确认文案；查询空态与真实无数据容易混淆。应统一有效筛选显示、范围校验和可执行的空态提示；退货默认值需业务确认。
2. **保护用户输入和状态变化。** 报销、调拨草稿、分类等部分表单取消时直接丢弃输入，与销售、盘点和分拣格的确认体验不一致；报销提交与撤回直接改变状态，确认需求应结合业务成本决定。统一脏表单保护，同时不改变业务状态机。
3. **增强工作交接与可追溯性。** 销售操作记录有笼统的“处理单据”；收货节点操作人及关联状态有不一致或延迟的观察；预占明细跨页返回后丢失条件并曾出现一次 503；分拣格管理可看到格号而销售作业进度未见格号；采购退货详情的原单号不能直接打开。先复现并核实各来源，再改善描述、刷新和返回体验。
4. **让常用操作可发现。** 多个列表的关键列或操作位于横向视野外，销售详情并列操作过多；150% 缩放后当前工作区标签曾不在可见范围。优先保证单号、状态、主要动作及当前标签可见，在实际窗口和缩放下回归。
5. **统一普通用户可读的文案。** 客户流水显示 UTC 原始字符串，凭证来源显示内部英文代码，部分页面出现“分位投影”“ACTIVE”等实现术语；采购计划、报表的菜单／标签／标题层级也需明确。保留业务口径和日期原值，只改善呈现。
6. **单独核实权限和规则建议。** 受限用户可见部分无权跳转的通知和操作入口；默认 PDA 不绑定仓库、商品分档单一商品归 C、从未出库商品立即计为滞销等涉及权限或业务策略，需先确认规则与影响。界面现象不等于已证实后端授权漏洞或算法错误。

## 隔离数据和操作边界

本轮使用显示“隔离测试 · 非正式”的本机专属测试环境；没有操作正式数据。为覆盖交接，在隔离库保留本轮合成销售单 `SL20261113001`、采购单 `PC20261113001`、收货单 `IN20261113001`、费用单 `EX20261113001`、盘点单 `SC20261113001`、已确认的采购退货单 `PR20261113001`、分拣格 `UI-AUDIT-01` 及其合成任务绑定、合成调入仓和待出库调拨单 `TF20261113001`；还有前轮合成用户与分类。详情及未提交的具体状态见续记。未提交盘点、执行退货出库或实际收付款。不得将这些样本当作正式业务数据，也不要为了整洁删除。

## 建议的后续验收顺序

先在单独整改计划中对问题去重、确认规则和权限归属，再按“误导/数据输入风险 → 交接与权限 → 列表/表单一致性 → 排版细节”处理。每项修复应对应界面复现步骤和岗位回归；PDA 真机、实体打印、Windows、外部服务和未准备的业务状态须单列真实验收，不能由代码或 API 检查替代 GUI。

本轮结束时已关闭本次测试标签和预览服务，并在确认数据库实际挂载为具名卷且无 tmpfs 后正常停止本批容器；卷、容器和测试记录均保留，其他既有容器未停止。前轮结束时设备登记待确认，随后用户确认并在补测中完成了合成设备登记与绑定。最新覆盖以补测记录为准。
