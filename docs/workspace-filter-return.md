# 工作区列表筛选与详情返回

## 已应用条件与返回目标

工作区继续以现有 `tabs[].path` 和合并页 `viewPaths` 保存路径；不新增跨页面查询缓存。裸列表返回和顶部菜单经 `getWorkspaceListPath` 取该列表原路径，验证页面与工作区 key 一致。不存在原列表时仍打开指定列表；显式 query、明确清空及新建来源参数保持调用者的目标。合并页只读取指定子视图原 query，财务组菜单仍遵循原有权限与最后子页规则。

关闭详情/表单标签先规范化 pathname 再匹配 `listPath`，带 `focus`、`edit` 或来源参数时也能识别所属列表。只关闭当前详情；非活动标签关闭不改变当前页。原有脏稿确认、切换保留输入、新建来源隔离继续使用原工作区机制。

## 查询作用域

已挂载列表读自身 `TabPathContext`，避免隐藏页从其他标签 URL 读取默认日期或关键词。`useWorkspaceSearchParams` 提供稳定的自身参数与普通 Router setter；隐藏页禁止改其他标签 URL，没有标签上下文时沿用普通 Router。新接入采购、采购申请、调拨、两类退货、日志、批次和承运商账号页。现有销售、收货、库存、商品等自身路径实现复用。

采购/销售退货共用组件，但类型由自身路径决定。拣货批次已应用筛选随 URL 保存；打开 `waveId` 详情保留查询，关闭只移除详情上下文，明确清空仍清筛选。承运商手选账号同步原 `carrierId` 参数，保留原查询和搜索草稿；显式跳转另一账号、脏稿切换确认继续生效。

局部 state 筛选仍由 KeepAlive 组件实例保留；内联详情关闭不额外重置查询。独立 full-url 页（如条码打印查询）保留其原身份，新菜单入口不擅自合并不同来源查询。

## 验证范围

`frontend/src/lib/workspaceListNavigation.test.tsx` 使用真实菜单、工作区、路由组件和合成空页面，覆盖公共入口与全部有固定归属的模式路径（含 query）；不能代表每页实际业务详情已经验收。

`useWorkspaceSearchParams.test.tsx` 验证隐藏读取/写入隔离、显式重置及历史；`workspaceListPages.test.tsx` 验证实际调拨、申请、双退货、日志、批次组件；采购筛选/导航和承运商导航另有实际组件回归。测试列表API用合成 mock，未连接后端或执行真实业务写入。普通适用单元测试与受阻 relatedEvents 探针分开管理。

本轮完整页矩阵、红绿日志、反向证明、最终静态检查及补丁哈希位于仓库外任务报告。GUI、Windows34项、PDA、实际打印仍未执行；不以 jsdom、类型检查或构建替代设备验收。
