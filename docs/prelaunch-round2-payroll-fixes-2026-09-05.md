# 第二轮工资累计与跨月依赖修复

本文件对应 `docs/prelaunch-second-audit-2026-09-05.md` 的 R2-03/04。范围为工作区实现与本机独立测试库验证；未提交、未发布、未修改生产数据。延续项目已采用的普通累计预扣口径，不新增其他个税优惠、追溯补税或历史凭证修订流程。

## 现行计算与依赖规则

- `calcMonthlyTax()` 的 `accumTaxable` 表示累计收入减累计扣除的完整净额，允许为负；税额和实发继续不为负。`hr_tax_accumulated.accum_taxable` 与工资行 `taxable_income` 保存完整累计净额，后者沿用既有累计含义。两列已是有符号 `DECIMAL(16,2)`，无需修改旧迁移或新增列。
- 例如持续任职、一月应发 0、二月应发 10000、无社保：一月累计为 -5000，二月累计为 0，二月税额为 0。低收入月份的未用扣除不丢失，累计转负不会自动返还此前已扣税款。
- 核算按员工当年任职起月逐月校验。已知入职日期时，从当年一月或入职月中较晚的月份开始；入职当月按一个月处理，创建工资单不带入尚未入职员工。每年重新累计，上一年税额和扣除余额不结转。
- 对没有入职日期的历史员工，以其在本账套首张工资所属期为可知起点；此前扣除不会被凭空补计。以后年度仍从一月连续核算。禁止补建会改变已有核算起点的更早工资，包含跨年补建。首次启用时应先核实员工入职资料与此前工资记录；缺少年内工资历史时不能把该数据缺口自动当成零收入。
- 前置月份必须有且仅有该员工一条有效已核算/已发放明细及对应台账。缺工资单、缺员工明细、草稿月份（含已录入的零收入月）均返回 409，提示具体前置月份。逐月重新推导累计值，与实际明细及台账对照；不再只取紧邻前月，缺失直接归零。
- 可连续核算多个尚未发放月份。发放时再次重验整条累计链、当前明细及台账，且前置月份必须已发放，保证“累计已预扣”具有实际发放依据。新员工从其任职起月检查，不要求发放其入职前月份。历史后月已经发放、前月尚未发放时，拒绝补发前月并提示人工复核。
- 后月已经核算或发放时，允许上游同一正确月份执行结果完全不变的重复核算；会改变工资、社保、税额、累计或实发的重算返回 409，整笔事务回滚。补建/编辑同年度上游工资同样拒绝，避免改变后月已依赖的事实。本次采用明确拒绝规则，没有添加撤算入口，也不会悄悄把后月重置为草稿。

## 锁与历史兼容

所有 HR 写入口（建员工、建工资、草稿录入、核算、发放）先复用 `accounting.period-lock.lockAccountingCompany()` 锁定真实账套行，再锁工资单、员工明细及年度累计台账。账套级锁比单年度锁更宽，但可保护尚不存在的月份，并与发放凭证及会计期间关闭保持一致锁顺序。跨月并发后发起的事务在取得锁后读取已提交累计，不使用等待前的快照。当前没有员工编辑或社保比例写 API；以后新增这些入口必须采用相同锁顺序并执行依赖保护。

历史正确的核算记录在逐月复核一致时可继续使用，不要求为所有记录补新版本字段。历史截零、逆序形成的陈旧台账会明确拒绝发放或作为后月基线使用；没有依赖后月且未发放的月份可重新核算。已有依赖后月的错误链，或涉及已发放月份的错误链，需要专门人工复核及另行授权的修订方案；本次不会修改旧凭证、自动补账、直接重置状态或静默清除台账。旧版没有明确工资录入标记的核算单，仍保留前轮禁止直接发放的保护。
