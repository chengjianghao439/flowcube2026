# i6310pro 原生扫码广播接入

## 现场证据与范围

- 设备：i6310pro，Android 12。设备自带扫码程序能识别条码；有焦点的记事本和极序 Flow 库存查询输入框能收到字符。v0.10.6 中用户主动开启原生无焦点接收后，现场确认 PDA 各作业页直接按硬件扫码键均正常；关闭后，库存查询点输入框仍可收到字符。设备扫码输出的具体设置页未找到。
- 既有 `usePdaScanner` 只监听 WebView `document.keydown`；作业页按用户要求不自动聚焦输入框。以上观察支持“键盘模拟输出依赖输入焦点”这一接收链路问题，不代表库存接口故障。
- 商家提供的 `Scanner-SDK-20241121.zip` 内有中英文开发文档、示例 APK/工程和两份不同版本的 JAR。示例工程依赖 `DeviceManagerNew_v231010.jar`，代码在 `onCreate` 调用 `ScanManager.switchOutputMode(0)`，在 `onResume` 读取当前广播 Action/字段并注册接收器。本项目复制的是示例工程实际依赖的 JAR；SHA256 为 `af1ec1ed88a965f88f0a2ca1598d2c9961e25e7cb460114e0fc96a52084a439c`。
- 厂商文档默认广播 Action 为 `android.intent.ACTION_DECODE_DATA`、字符串字段为 `barcode_string`；`getParameterString` 可读取设备上已改过的值。输出模式 0 为广播、1 为键盘。文档另提供 Android 11+ 设置广播，但本实现使用示例工程对应的 SDK 读取原模式与参数。

## 实现约定

- v0.10.6 的原生广播桥默认关闭，供 i6310pro 真机验证。现场确认后，v0.10.7 在插件首次加载时默认启用，以 `RECEIVER_NOT_EXPORTED` 注册厂商广播接收器并切换输出模式；非厂商设备失败时保留键盘路径。v0.10.7 的「库存查询」仍可在本次运行中主动关闭/重新开启；v0.10.8 已移除页面上的临时开关，原生桥的模式控制能力保留。退后台时暂时恢复原键盘模式，回前台时重新启用；销毁或异常退出后恢复设备原模式。切换前同步记录待恢复状态，进程异常退出后，下次启动先恢复再启用。
- 仅转发 Action 匹配且含非空条码字符串的广播。前端 `usePdaScanner` 把原生完整条码与既有键盘聚合结果送入同一回调和 1 秒防重复窗口；同一次扫描若由广播和键盘重复上报，静默丢弃跨来源副本。非厂商设备或 SDK 不可用时保留键盘路径。
- 不给作业页增加隐藏输入框或自动焦点；`PdaScanner` 手输框已打开时，硬件广播扫码仍可完成当前操作。v0.10.7 收货上架页允许点扫码区域后手动输入完整库存/库位条码；v0.10.8 已按用户要求统一为点击「手动输入」按钮才弹键盘，仍经过原有条码解析、单据归属、状态及库位校验。调拨出入和销售退货上架暂保持强制扫码。

## 验证边界

- 前端原生事件、键盘/广播去重及手输框状态有组件测试；Android 模式恢复和广播内容校验有 JVM 测试。Debug APK 本地编译验证只证明可构建。
- i6310pro 上 v0.10.6 已由用户确认：主动开启后，无焦点硬件扫码在 PDA 端正常；上架页的提示框原本不是输入框，点它不会弹键盘。v0.10.7 发布后，用户确认默认无焦点扫码、点上架扫码区域弹键盘手输、退后台后记事本恢复键盘扫码均正常。跨应用伪造广播拒收仍需具备外部测试应用时验证；`RECEIVER_NOT_EXPORTED` 不改为无保护的 `RECEIVER_EXPORTED`。
- v0.10.8 已移除库存查询页面上的模式开关，并将拣货、上架、分拣、退回、改单、盘点和库存查询等条码入口统一为底部扫码条及「手动输入」按钮；直接扫码与手动输入查询入口保留。已安装的 v0.10.7 不会自动呈现这些界面变化，需更新到 v0.10.8；本版 i6310pro 真机操作仍待单独验收。
- Debug APK 与已发布包签名不同，不直接覆盖现场正式包。安装方案须先保证可回退和保留设备登录/绑定状态。
