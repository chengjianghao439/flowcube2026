# 仓库范围与导出修复

本任务在 `codex/prelaunch-fixes-20260905` 工作树实现，未发布。对应原审计 F05、F06、F08、F12–F14。

- 塑料盒列表、详情、流水、创建、删除均传递用户仓库范围。空盒创建仅接受启用商品 / 仓库及目标仓的启用库位，商品单位与名称来自服务端；删除在容器行锁内复查余量和任务锁。
- 采购门户与采购列表采用相同的仓库范围条件。客户对账门户由对账明细 → 账款 → 销售单的客户 ID 关联，不按名称匹配；历史空明细、混合客户或无法关联的单据不猜测归属，财务总列表保留原始记录供核查。客户改名不改历史名称快照。
- 列表型导出使用 `utils/exportRows.js` 有界分批读取，总数超过 10,000 明确拒绝；检测读取期间总数变化或重复 ID 并提示重试。新增唯一 ID 排序，不能通过放大公共列表 pageSize 绕过分页。
- 资产、期间、税务调整导出接受请求头解析后的账套，查询参数不能覆盖；涉仓资料导出使用服务端仓库范围。分拣格导出调用管理查询，修正旧导出错误使用 PDA 查询签名。
- 固定资产状态 1/2/3 分别为使用中/已提足/已处置；导出日期采用北京业务日期。

首轮真实 MySQL / HTTP 回归 `prelaunch-scope-export.smoke.test.js`：旧实现 12 失败；实现后 12 通过。后续扩展验证、最终 lint 和领域回归结果在总修复报告汇总，不能将此首轮计数当成最终验收。


复核补齐：另有账款、收付款单和对账单三个出口使用 pageSize=10000，但公共分页实际限500，同步改为分批读取，原筛选保持不变。全部三个出口增加503条与10001条上限回归，列表按 created_at、id 唯一排序。专项现为32项通过，含真实 HTTP 双账套 Excel（头覆盖query）、日期/状态、停用主数据、同名/混合归属及删除等待锁后的库存复查；纯导出分页2项通过。三个新增财务出口使用受控分页响应验证上限和筛选，客户及双账套使用真实SQL/Excel，不将两种证据混称。
