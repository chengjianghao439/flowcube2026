## 偶发问题和交互观察

- 历史预占 503 的应用码为 `INVENTORY_RESERVATION_SNAPSHOT_BUSY`，来自快照构建并发或快照缓存容量保护。历史同条件请求相邻出现 503 和 200，结合本次观察到的重复读取，构建重叠是优先线索。现有日志无法确定历史命中了哪条限制。正常 Chrome 打开预占、应用 `SL20261112001`、打开原单并切回库存，筛选仍在。日志中 5 次请求均返回 200，首次打开及切回各见两次相同读取。当前预览使用 Vite 开发模式和 React StrictMode，待在构建产物中对照请求次数。现有快照与预占专项 23 项通过。
- 批次效率和 PDA 异常用鼠标往返三轮，页头均切换到目标，本轮未再见停留。
- 复核和打包连续操作时，上一页扫描的普通库存 `I` 码在打包页会被按取货标签判定，提示本任务无有效盒取货记录，箱内仍为 0。改用页面支持的商品码装入 1 件。记录为交接文案问题，扫码和装箱规则本轮未改。
- 打包页曾同时显示“箱贴尚未打印完成”和可点击的“完成打包并进入待出库”。模拟回执后点击可继续，点击前页面仍显示排队。记录提示与当前可执行动作的同步问题，打印门槛沿原服务判断。
- 批次详情通过 `waveId` 打开时曾出现两个同名“批次拣货”工作区标签，列表与详情所在标签不易区分。供应商退款草稿页面仍用原生账户下拉和日期日历，已实际完成填写。这些记录供后续界面调整参考。

## 数据恢复和回归

- 原隔离库出库后备份和本轮专属库最终快照分别用 SHA-256 核验，分别导入新的禁网 MySQL 8.0.46 容器。两次均确认目标为全新空库，数据库 UUID 与源库不同。各恢复 165 张基表、1 个视图、4 个触发器。回导后分别逐字节比对 57 和 97 条 `INSERT` 语句。原库快照核对已出库箱 `L000001` 的 3 件，本轮快照核对已出库任务、销售退货及 5 元退款草稿。恢复副本应用登录与灾难切换待验。
- 会计期间专项在独立回环副本执行 `npm run smoke:accounting-period`，22 项通过，涵盖月结与年结、反结账及扫码盘点。原隔离库和 GUI 库的会计记录未用该套件清理。环境内存按顺序使用，两个恢复容器和会计副本均退出码 0、未发生 OOM，各自具名卷保留。
- 普通 Chrome 测试标签和预览已关闭，专属 GUI 库正常停止并保留卷。原先正在运行的隔离库继续运行。业务代码留在本地工作树。本轮只补验收和记录，业务待决规则以及 Windows、实体 PDA、实体打印仍待对应验收。
