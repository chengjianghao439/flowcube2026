# 同类订单页面对齐

后续用户已要求恢复旧版销售列表，现行规则见 [旧版布局恢复](sale-classic-layout-2026-09-05.md)。以下保留本轮历史方案，不再代表销售列表当前布局。

用户选择状态快速分类统一放在标题下方，不在表格底部重复添加。

- 销售列表增加“运输 / 承运商”列与预览字段，使用 API 已有 carrier、freightTypeName；现付/到付是运费方式，不冒充运输类型，也不将订单所选承运商声称为每票运单的实际承运商。未指定显示原始空值提示。
- 采购、销售、收货复用 OrderStatusFilter，下划线表示当前状态；状态切换保留其他 URL 查询并回第一页。采购、销售、收货均仅显示分类名称，分页继续显示服务端总数。销售标题下补充简短业务说明：管理销售订单，查看占库、发货进度与承运商信息。
- 运输列使用新的列宽存储键，避免旧六列宽度挤占；销售保持七列，无常驻数量、回款、备注列。

## 横向检查结论

对照采购、销售、收货、采购申请、采购计划、调拨、采购/销售退货与物流运单列表实现：采购/收货/调拨/退货已经使用相近的 PageHeader、DataTable、查询与分页结构，无需重做布局。销售查询入口与采购一致放在标题右侧，单号等条件统一在查询弹窗输入；销售保留按需预览。

本轮明显差异：采购/收货缺少快捷状态入口，采购申请和采购计划页头说明过长，物流运单日期/条数单独套卡片。本轮分别补齐共享分类、缩短页头描述、取消运单摘要额外边框。审批、计划转单等业务规则不变。

本地实页验证：销售运输列空值正常显示；采购草稿分类、收货待上架分类切换成功；采购操作列加宽后“详情”不再折行；采购申请、采购计划和物流运单均正常加载。当前销售首屏没有已指定承运商的记录，没有制造业务数据补截图；本轮未检查所有承运商名称长度或运单状态。收货分类沿用原始订单状态筛选，行内仍可显示收货异常投影，不修改已有状态规则。

静态验证：tsconfig.app 类型检查通过；lint 0 错误、5 条已有警告；8 项相关测试通过；ERP 构建通过；git diff --check 通过。AGENTS.md 与覆盖索引已同步，未发布。
