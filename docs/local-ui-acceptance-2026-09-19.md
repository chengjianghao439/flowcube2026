## 第三轮补充（同日）：虚拟滚动与弹窗尺寸记忆（浏览器实测）

环境：本机 5173，管理员档案 `flowcube-gui-0917`，任务会话 `fc-rt-1`，viewport **1280×633**。本轮只做只读页面验收，未触发业务写操作。

### 虚拟滚动：商品列表在 2637 行下确实只渲染窗口内的行

- 数据量：`flowcube_dev8.product_items` **2637 行**（远超 ≥200 的触发阈值；上一轮之所以没验成，是误用了只有 4 行的销售列表）。
- `/products` 打开后：`tbody tr` 只有 **16** 行，而滚动容器 `scrollHeight = 126702px`（≈2637 行 × 48px）——渲染量与总行数解耦。
- 滚动到中部（`scrollTop = 63351`）后首行内容由 `SC-sale-55076f89…` 变为 `NTEG-CANF-P-…`，DOM 行数仍只有 28 → 行是**回收复用**的，不是"只渲染了第一页"。
- 控制台无错误（`agent-browser errors` 为空）。

### AppDialog：尺寸记忆成立；但**位置不可拖动**（文档表述已收窄）

在「销售 → 新建 → 添加商品」打开的 `ProductFinderModal` 上实测（`dialogId=product-finder-v2`，默认 1200×730，minHeight 560，maxWidth 95vw，maxHeight 90vh）：

| 步骤 | 实测结果 |
|---|---|
| 拖右下角手柄放大 | 1200 → **1216** = 95vw×1280；高保持 **569** = 90vh×633 —— 命中上下限钳制 |
| 拖手柄缩小 | **1016×560**（高度被 minHeight=560 夹住）；写入 `localStorage: flowcube-dialog-size-product-finder-v2={"width":1016,"height":560}` |
| Esc 关闭后重新打开 | 恢复 **1016×560**（≠ 默认 1200×730），并按新宽度重新居中（x=132）→ **尺寸记忆成立** |
| 按住标题栏拖到 (600,300) | 位置**仍是 (32,32)**；localStorage 里只有尺寸键、没有位置键 → **弹窗不能拖动移动** |

结论：`AppDialog` 的实际能力是「右下角拖拽**改尺寸** + 按 `dialogId` 记忆尺寸（localStorage）；**位置每次打开重新居中计算、不持久化、不可拖动移动**」。此前 AGENTS §9 与本仓库相关文档写的「可拖拽」容易被读成"能拖着挪位置"，已收窄为准确表述。

**待用户确认**：若当初「可拖拽」的意图确实是"能拖动弹窗位置"，那属于**尚未实现的功能**（不是回归）——需要明确后再决定是否实现，本轮不擅自实现。

**浏览器 dev 模式的已知代价（文档已说明，实测一致）**：设备凭据只存内存，**任何页面重载都会丢失绑定**、回到受限模式。所以「先登录再绑定」必须在同一次页面生命周期内完成；本轮第一次尝试就是被 `auth login` 的整页跳转清掉绑定而失败的。

### PDA 聚焦规则（AGENTS §9）运行时两面

- **反面（扫码/浏览页不得抢焦点）**：`/pda`、`/pda/inbound`、`/pda/transfer`、`/pda/transfer-out/260`、`/pda/stockcheck` 上 `document.activeElement` 全是 `BODY`，且**页面没有渲染任何输入框** → 进页面不会弹出软键盘挡住扫码视野。
- **登录页正面（需要输入 → 自动聚焦）**：`/pda/login` 挂载后 `document.activeElement.id === 'pda-username'`，自动聚焦**生效**。
  - 踩坑记录：用 `input.autofocus`（DOM 属性）判断会得到 **false** —— React 的 `autoFocus` 是挂载时调 `.focus()`，并不写这个属性。本轮先据此误判成"聚焦失效"，改用 `document.activeElement` 才拿到真实结论。**判断聚焦一律看 `activeElement`，不要看 `autofocus` 属性。**
- **「手动输入」正面（点击后才出现输入框并聚焦）本轮未取到**：有数据且允许手输的只有空盘点单；其余扫码页（上架、调拨调出、销售退货上架）都显式 `allowManualEntry={false}`（强制扫码场景，属设计）。该方向由组件实现（进入手输模式后 `setTimeout(() => input.focus(), 80)`）与静态守卫 `test:pda-scan-focus` 覆盖。
