## 3. 验收项 A · Windows 桌面端

> **前提先确认**：正式安装包（§1）**能否指向一套受控测试环境**（测试后端/测试库）。
> **能** → 按下面完整执行；**不能** → **只验「安装 + 只读」两项**（安装成功、版本号、登录、只读页面），
> **关键作业与打印仍记未验**，**不得**为凑验收在生产环境造交易。

**准备**
- 一台 Windows 机器，装有**低于 0.11.4** 的正式版（记录实际旧版本号与安装路径）。
- 从 §1 的 Release 地址取安装包，**先核对 sha256** 与 §1 一致再安装。
- 记下当前系统时间（用于对日志时间线）。

**步骤**
1. 启动旧版客户端 → 打开更新检查（或等待自动检测）→ 观察是否提示发现 0.11.4。
2. 触发下载 → 观察下载完成 → 触发安装/重启。
3. 安装后启动，确认版本号显示 **0.11.4**。
4. 用既有账号**登录**。
5. **关键作业**（受控测试环境下）：**不能只打开页面**。要与 §5 一致地走通一条真实作业链——
   由真实客户端**领取本批打印任务（job）→ 实际出纸 → 由客户端回传完成**；在具备该能力前，
   作业与打印**均为未验**。

**判据（全部满足才算通过）**
- 更新提示出现且指向 0.11.4；下载完成、安装成功、重启后版本号显示 0.11.4；
- 登录成功；
- **（受控环境具备时）**关键作业可执行，且打印任务由真实客户端领取 → 实际出纸 → 客户端回传完成。

**证据**：更新提示截图、下载完成截图、安装后版本号截图、登录后截图、安装包 sha256 记录；
（受控环境具备时）作业链各步截图与出纸照片。

**未验状态**：**待现场**。若最终无法提供受控测试环境，则本项**仅安装/只读部分可验**，
作业与打印**保持未验**。

## 4. 验收项 B · Android PDA：原地更新 148、扫码、断网/重启恢复

**准备**
- 一台 Android 设备（记录型号与 Android 版本），**允许安装/更新本应用**。
- 从 §1 取 APK，**先核对 sha256** 再安装；记录原已安装版本（若有）。
- 用**测试账号/测试仓库**登录，不接生产单据。

**步骤**
1. **优先「原地更新」**（覆盖安装新版本到旧版本之上），**不卸载、不清应用数据**——
   卸载/清数据会掩盖「升级后旧状态是否可用」这类真问题，只在原地更新确实不可行时才另做说明。
2. 确认版本为 **0.11.4 / versionCode 148**。
3. 登录 → 绑定 PDA 设备（沿用现场合法的设备登记流程）。
4. 对一个**测试任务**执行扫码（至少一次真实扫码取码）。
5. **恢复用例（必须在真实写操作之后）**：先做一次**真实写操作**并**制造丢响应**（网络中断/代理扣住），
   使界面进入**待确认**；**当场记录原请求键、原任务号、原箱定位**；
   然后**断网恢复**、**重启应用**，再**对照后台实际状态**确认这三项仍指向原目标。
6. **重新登录只在确实被要求时**做（例如凭据确实失效）；**不得用「清掉记录/清数据」让用例通过**。

**判据**
- 原地更新成功、版本号正确、原应用数据未丢；
- 设备绑定成功（与后台登记一致）；
- 真实扫码能取到码并被系统接受；
- 待确认期间记录的原 key / 任务 / 箱定位，在断网恢复与应用重启后**仍指向原目标**，且与后台一致；
- **不出现**「靠清除记录或清数据才通过」的情况。

**证据**：更新过程与版本截图、绑定成功截图、扫码成功截图、**待确认时的原 key/任务/箱记录（截图或界面读数）**、
断网与恢复截图、重启后截图、后台状态截图、APK sha256 记录。

**未验状态**：**待现场**。

## 5. 验收项 C · 取货标签/箱贴出纸、贴货、实扫 → 分拣 → 复核 → 装箱

**准备**
- 一台**已登记并在现场可用**的标签打印机（记录打印机编号/绑定仓库）。
- **测试用**标签纸与纸箱若干；测试任务一套（测试仓库、测试商品）。
- 明确**只出测试纸**：标签内容属于测试任务，不贴生产货、不混入生产单据。

**步骤**
1. 触发取货标签打印 → 观察**实际出纸**，核对纸上内容与任务一致（任务号/箱码/数量等）。
2. 把标签**贴到对应货/箱**上。
3. **真实扫码**走下游：分拣 → 复核 → 装箱（逐步做，每步留一次实扫记录）。
4. 装箱完成时触发箱贴打印 → 再次确认真实出纸。
5. **打印闭环必须由真实客户端完成**：真实客户端/桌面端**领取本批 job → 实际出纸 → 回传完成**；
   **API 模拟核销（`claim-client` + `ackToken` + `complete-client`）不等于实际出纸**，不能替代本项。

**判据**
- 每次打印都**实际出纸**且内容与任务一致；
- 实扫的每一步在后台产生对应记录（分拣/复核/装箱状态按预期推进）；
- 装箱完成后的箱贴同样出纸且可贴；
- 作业链由**真实客户端**领取 job 并回传完成。

**证据**：出纸照片（含标签内容）、贴货照片、各步扫码界面截图、后台任务状态截图、客户端领取与回传记录。

**未验状态**：**待现场**。

## 6. 现场安全边界（必须遵守）

- **不在生产库造真实交易**：所有测试任务在测试仓库/测试数据范围内进行；不得为验收而生成生产单据。
- **只用测试纸**：打印类验收只出测试标签，不贴生产货物、不让测试标签进入真实物流。
- **不伪造证据**：出纸与扫码必须真实发生；截图与照片须当场产生，不拼接、不代填。
- 设备/打印机/仓库等登记与解绑，**沿用现场合法流程**，不绕过权限或设备校验。
- 现场结束后按现场约定收尾（设备解绑、任务收口），不物理删除历史记录。
