# 全局搜索：历史查询、结果信息与分页

右上角全局搜索移除日期下拉框，输入关键词即搜索全部历史记录。前端 `/search` 请求传 `q` 与分页参数；后端 controller 不再接收日期筛选，service 不再生成创建日期条件。旧客户端发送 `startDate`、`endDate` 也不会缩小搜索日期范围。

保留现有仓库范围（含调拨任一端匹配）、软删除过滤和参数化关键词。取消每类 5 条总上限，每类每批 20 条，内部按 ID 降序使用 `beforeId` 游标继续查询，直到加载完匹配记录；单次读取 21 条判断是否有下一批，避免一次无界读库。API 自动读取所有类别的后续游标，全部成功后展示完整搜索结果；界面没有加载更多或翻页控件，续批失败不返回残缺结果。

新客户端发送 `paginated=1`，响应 data 为 `{ items, nextCursors }`；续页携带白名单 `type` 与正整数 `beforeId`，只查询该类并重新执行范围过滤。未携带分页标记的旧客户端仍接收数组。关键词变化、清空、Escape、跳转和卸载使首批与续页响应失效。

客户、供应商和商品显示名称、编码，不再重复显示编码。客户与供应商补充联系人、电话、地址；商品补充供应商型号、型号、颜色、单位；单据按类型补充仓库、经办人、关联单号或申请/报销标题。有值才显示。此次只丰富显示内容，关键词匹配字段不扩展。

输入沿用 300ms 防抖；新关键词立即清理旧结果，只有当前请求可以写回结果、加载和错误状态。清空、Escape、选中跳转和组件卸载会使旧请求失效。补充“正在搜索全部历史记录”和查询失败提示，删除结果底部“不限制日期 · 每类最多显示 5 条 · 点击打开”说明。返回类型与现有服务字段同步，移除不安全类型转换。
