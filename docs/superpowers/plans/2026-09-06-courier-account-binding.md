# 快递月结账号绑定实施计划

目标：在现有承运商直连基础上增加仓库人员可用的月结账号页面，保留真实官网登录与平台开通的边界。

设计：复用承运商查看/编辑权限和已有字段，不新建密钥数据库。页面选择已有承运商、快递公司、月结号和常用服务；后台使用默认凭据组，返回脱敏的准备状态。保存仅代表本地资料已保存；管理员在服务端配置已经完成平台验收的账号清单后才允许从简易页面启用正式自动下单。未知回执及历史请求快照仍沿用原规则。

- [x] `tests/carrier-account-binding.test.js`：先验证缺少接口配置、沙箱、未验收账号不能启用，凭据脱敏、账号更换自动暂停、并发修改拒绝。
- [x] `backend/src/modules/carriers/carriers.binding.js`：状态投影、行锁保存；routes/controller 注册 GET/PUT `/:id/account-binding`，严格输入及现有权限。配置产品名称和已验收账号从专用服务端变量读取。
- [x] `frontend/src/pages/carrier-accounts/`：独立页面与表单，清楚显示资料/接口/账号验收状态；仅用中文服务名，不采集密钥、手机号验证码或重量。承运商页面提供入口。
- [x] 同步 API 类型、路由注册、AGENTS.md、接入指南和环境示例。
- [x] 离线业务测试、前端交互测试、lint、类型检查、本地页面验收。真实官网登录遇平台封禁则保留明确待办，不绕过验证、不假报绑定成功。
