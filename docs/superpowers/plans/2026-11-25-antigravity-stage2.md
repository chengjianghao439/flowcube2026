# 反重力第二轮 Web 复测与修复

**目标** 在 `codex/frontend-ui-audit-plan` 的当前工作树复测第二轮报告，修复能复现的交互、可达性及视觉规范问题。以当前桌面规范、现有业务操作和销售样板为依据。

**基线** `44ccb1ffc675ce563b0fa4a280a1d49fd014e7b0` 及开工时的未提交修改。浏览器使用三档桌面视口与本地合成数据。报告所有条目记录观察、判断与修后结果。

- [x] 成套配件、补货建议、库存总览与流水、改价、仓龄的默认列、操作可达性、统计区与语义色。
- [x] 会计科目、商品分类、部门对照及仓库结构各子页。检索、层级展开、权限和查询恢复跟随现有约定。
- [x] 资金看板、财务与会计常规页、业务统计、运费对账、条码查询和打印模板。核对页头动作、窄窗、控件高度及信息层级。
- [x] 小满欢迎区、工作区顶栏及订单表单。重验登录错误态、采购明细和盘点下拉，保持销售样板的行内校验。
- [x] 核对六组跨页建议与现有规范，按实际适用范围修改。验收三档视口、相关测试、前端类型、改动文件 lint 与守卫，补记争议项和验证范围。

## 集成复核

- 会计科目编辑与菜单操作可读名称均包含科目编码和名称。普通分拣格管理入口使用列表路由，订单任务链接仍进入独立交接。分别加入失败到通过的回归。
- 资金流水使用实际格式的 27 字符合成退款单号验证。1280×720 下原链接超出单元格 96 px，调整后为两行，右侧溢出 0 px。
- 资金页面收到错误响应文本时，共享查询错误状态仍能渲染重试入口。结构化错误详情沿原行为。
- 跨页共性实际收敛到顶栏、桌面录入、页头操作、相关摘要和商品身份列。允许长文本选择器变高以及专业宽表在表内滚动。共享 Radix 下拉可能生成隐藏的表单代理，核验以可见控件为准。

## 验证结果

- Node 22 前端全量 444 个文件、4,085 项通过。TypeScript、改动文件 ESLint 与前端生产构建通过。首次全量中，采购校验和待我审批两条旧断言在开工基线也失败，现与当前交互一致。顶栏用户名长文本已按原完整展示守卫改为换行。
- 样式兼容测试的常规桌面与 PDA 边界各比较 2,070 项，均无差异。前端约定、日期、会话、轮询和数量精度守卫通过。
- Chromium 按三个视口复测报告发现，使用本地合成响应和可复核数据行。部分专业表在 1024×576 保留表内横滚。业务写入数据库、生产部署、PDA 真机和实际出纸另行验收。
- 本地浏览器与临时服务已关闭，修复保留在审计工作树。
