# 历史应收修复与跨模块一致性扫描实施计划

> 按用户已授权范围在当前任务顺序执行，不另建任务或自动委派。

**目标：** 修复两笔已确认的生产应收及对应历史已发数量，检查其他模块的来源单据、数量和金额投影。

**实现：** 一次性定向修复脚本默认只读预检，显式 apply 才写入；数据库行锁、精确来源/金额守卫、依赖检查、事务内审计事件、提交前备份及幂等标记共同限制写入范围。通用只读扫描脚本保留检查 SQL、全量异常计数与有界样本，不能自动改业务事实。

**技术：** Node 22、mysql2、MySQL 8、node:test；不变更表结构及已执行迁移。
