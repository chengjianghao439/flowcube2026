# 客户与供应商往来明细实施计划

> 执行方式：当前会话顺序实施，保留已有财务/采购及快递改动；不提交、不发布。

**Goal:** 在客户、供应商列表打开该单位的跨结算方式往来明细，并明确现结/月结菜单名称。

**Architecture:** MySQL 增量迁移建立事务化往来事件，历史余额按启用时点结转，后续账款净额变化、直接收付款/退款、汇款单分别在原事务内记账；核销不重复改变往来净额。API 使用往来单位 ID、事件上界与批次一致性校验和有界分页，界面批量加载完整明细。

**Tech Stack:** MySQL 8、Express/CommonJS、React/TypeScript、React Query。
