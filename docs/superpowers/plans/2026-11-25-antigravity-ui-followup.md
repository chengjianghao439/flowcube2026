- [x] **财务、报表和表单**（P1-02、P1-05、P2-04、P2-08、P2-09、P2-10）。按删除权限渲染、确认及执行删除。凭证初始焦点落在标题，日期仍可主动展开。为核验中缺少名称或上下文的控件关联名称。固定资产对照接口拒绝非法数值，报表日期只显示行内错误。科目操作常显并提供动作与科目名称。
- [x] **导航、窄屏和官网**（P2-01、P2-02、P2-03、P2-05、P2-07、P3-03、P3-04、P3-05）。各菜单依照触发和路由变化收起，用户菜单支持键盘回焦。消息避开顶栏和窄屏操作区。验证小满、通知以及登录首屏在 1024×576 下可访问。核验商品与单据搜索共用的选项语义，以及官网对开发回退页的既有容错。
- [x] **表格**（P2-06、P3-02）。调整仓龄仓库列和盘点操作列的默认宽度，窄屏保留横向滚动和操作可达。按键分步核对销售和库存流水的列宽调整与适配。
- [x] **标题层级**（P3-01）。在报告列出的页面使用连续的标题层级，保持现有视觉尺寸，核对共享组件的嵌套用法。

## 修复前逐项核对

核对 Antigravity 11 月 24 日审计报告、原截图及同一工作树源码。浏览器复现使用本地 Vite、合成角色和可控 API 夹具。核验结束时已核对全部已跟踪文件与启动时一致。

| 条目 | 核对结论与修复依据 |
|---|---|
| P1-01 销售详情未保存 | 实际恢复钩子和脏状态仓库复现正常、非活动标脏、恢复活动解除。离开判定取真实操作状态，保持原恢复和请求保护。 |
| P1-02 只读账户删除 | 合成只读角色显示「删除」，后端路由独立检查 `finance.account.delete`。入口和确认都按当前权限处理。 |
| P1-03 采购数量 | 小数可能被恢复成上一次输入，清空会变成 0。现行采购接口在建单和改单都要求正整数，界面保留原文并提示。 |

| P2-07 单项菜单 | 权限过滤为唯一入口时，守卫和路由正确，顶栏却显示组名。改用目标入口名称。 |

## 修复后本地浏览器验收

- **只读与筛选。** 合成只读账号在资金账户可见「流水」，行操作菜单消失。合成管理员可打开并取消删除确认，关闭后页面指针恢复。只读账号打开销售、收货与库存三个列表，列表请求均正常，夹具未收到客户、供应商或分类读取。查找器跨工作区恢复由组件测试验证。
- **录入。** 采购录入 `1.5` 保留原文，显示正整数提示，修成 `2` 后提示消失。手工凭证初始焦点为标题，日历关闭，分录四类控件具有独立行名称。固定资产填 `-100` 时创建禁用且行内说明原因。业务统计填 `2026-02-31` 保留原文，只显示行内错误，原查询日期仍生效。
- **窄屏与宽表。** 1024×576 下登录报错后的帮助末行约 y=538。系统菜单可点击关闭并随路由收起，用户菜单键盘打开后可用 Escape 返回触发器。Toast 顶边在页头下 8px，可与菜单同时出现而保持菜单优先。通知列表可聚焦和滚到末条。盘点操作单元格没有横向溢出，按钮下半部能命中并打开详情。1600×900 下仓龄合成长仓名分两行，末行完整保留仓库编号。
- **范围。** 浏览器使用真实 Chromium、该工作树前端和本地合成 API，覆盖上述页面与交互。销售待确认回执使用组件及本地状态回归。本轮浏览器、Vite 和合成 API 均已关闭。发布构建、真实数据库、生产、Windows 和 PDA 真机留待按各自流程验收。
