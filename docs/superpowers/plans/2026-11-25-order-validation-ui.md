# 订单录入校验样式统一

**目标** 以普通新建销售单为样板，提交遇到可修正的录入问题时，在字段或明细旁显示原因，聚焦本表单内的第一处。保留输入及各单据校验口径。

- [x] 共享 `OrderFieldError` 复用销售单的小字、红色和无障碍提示。共享定位函数只在当前表单中寻找可用字段，支持重复字段名、隐藏的 KeepAlive 标签及现有虚拟行定位。
- [x] 采购新建与编辑、处置来源销售替换顶部可点击汇总。采购继续按正整数提交，保留数量原文和四位单价。普通及成套销售复用相同的字段提示。
- [x] 收货新建与编辑、调拨新建与编辑、采购与销售退货改用同样的字段提示。保留来源期限、数量额度、换算、入库及幂等逻辑。
- [x] 销售退款、供应商退款、报废、盘点新建与明细录入迁移可归属到具体字段或明细的错误。权限、取数、未知回执和其他请求错误沿各业务原入口反馈。
- [x] 执行 Node 22 定向回归、前端类型检查及改动文件 ESLint，用本地合成 HTTP 复验销售样板和典型单据，同步前端约定。

## 验证

- 100 个相关前端测试文件共 1,016 项通过。`tsc --noEmit -p tsconfig.app.json`、改动文件 ESLint、前端约定和数量精度守卫均通过。
- Chromium 本地预览以合成数据复验普通销售、成套销售、采购、收货、调拨、采购退货、销售退货及销售退款。空表提交时错误显示在字段或明细旁，焦点落到第一处错误。采购数量 `1.5` 保留原文并提示正整数要求，改为 `2` 后提示消失。
