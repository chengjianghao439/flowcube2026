# 发版成功路径 15 分钟目标

目标：保留同 SHA 测试、安全扫描、生产验收、三端发布和失败回退，将正常成功路径压到 15 分钟左右。15 分钟是性能目标，不是强杀上线/回退的超时。

现场基线：v0.10.1 浏览器部署约 15 分钟，其中 Tests 等待 183 秒、镜像构建 52 秒、页面验收约 527 秒；PDA 构建与部署并行，桌面 tag 构建约 4 分钟。最近异常运行卡在跨境 SCP 上传。

1. 用常驻 Playwright API 替换页面验收的逐次 npm CLI 启动；保留原页面、PDA 独立标签、受限账号 403 和允许访问断言。依赖锁定到预装浏览器的 1.55.0，随后端镜像交付，生产不再下载 npm 包。
2. 镜像传输优先尝试服务器通过短期签名 HTTPS URL 拉取本次 GitHub Actions artifact；验证归档 SHA256，失败明确降级原并行 SCP。短期 URL 仅走标准输入，不写日志或进程参数，不向生产发送 GitHub token。增加 SSH 复用，保留慢网络和回退预算。
3. 修正正式发布入口：等待本次 main 的 Tests、Security、Browser、PDA 全部完成后才打桌面 tag，避免三个发布者同时争用 GitHub 的单 pending 队列；等待对应 tag 的桌面构建并执行线上版本核对，不能以“请求已提交”冒充完成。
4. 测试先覆盖失败路径，再实现：浏览器真实本地夹具验证导航、权限和资源关闭；传输覆盖损坏归档、超时和降级；发布顺序与错误中止使用离线桩。接入现有 CI 测试入口，更新运维文档。
5. 跑发布回归、shell/YAML 语法、仓库守卫和反向验证。仅报告本地证据；真实 CI 耗时与中国服务器新下载路径要在获得正式发布授权后验证。

预期预算：检查 3 分钟 + 镜像构建/传输 2 分钟 + 应用切换/页面验收 3 分钟 + PDA 收尾 1 分钟 + 桌面 4 分钟 + 最终核对 1 分钟 ≈ 14 分钟。依赖网络、runner 排队和服务器负载，不保证异常网络仍低于 15 分钟。
