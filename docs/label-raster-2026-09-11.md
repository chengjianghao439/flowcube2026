# 标签中文与预览一致性修复

## 实现约定

标签 type 5–10 的画布布局统一在后端使用随包的 Noto Sans CJK SC 字体绘制，文字换行、裁剪、对齐与条码均落到整数打印点。二值化后的同一份像素生成 PNG 预览和 ZPL `^GFA`；编辑器不再独立绘制标签文字/条码。内置兜底标签也使用相同渲染器。打印数据不发送到第三方。

模板 `layout.dpi` 支持 203、300，历史缺省 203；纸宽 30–120 mm、纸高沿用编辑器 40–500 mm。预览缩放只影响显示。DPI 应与实际设备分辨率一致。条码按编码后的模块数取整数点宽，保留静区，HRI 包含在元素高度内；非法条码、尺寸不足或超出纸张明确报错。文字按元素框换行并裁剪。

手写 `format=zpl` 模板保留原正文替换规则，已入队/补打快照不重新绘制。货架、库位、商品标签的幂等请求返回已保存任务内容，避免重绘结果与原队列内容不一致。模板中没有业务样例值；预览取数仍沿用模板查看、来源业务权限及仓库范围。队列份数、幂等、事务、派发与回执协议不变。

## 接口与运行边界

`POST /api/print-templates/render-label` 要求登录及 `print.template.view`，只渲染传入的 `layout`、`data`、`paperSize`，不读取业务记录、不入队。返回 `imageDataUrl`、毫米/点尺寸及 DPI，不返回 ZPL，响应不缓存。真实记录仍由原 `preview-data` 接口校验来源权限和仓库范围。按当前 `req.user.userId` 限流，每分钟 120 次；编辑器防抖 200 ms，内容未变的缩放/选择不请求，隐藏页及账号切换取消旧请求并撤下旧图。错误提示保留条码宽度/边界等具体原因。

渲染线程只接收需要绘制的字段与布局白名单；至多 100 个元素，队列至多 16 项，超时 15 秒。文本最多 4096 字符，超出加省略号，最终按元素框裁剪；未使用的长装箱明细不影响完成装箱。条码最多 256 字符并通过实际码制校验，不能截短条码。最大画布 120×500 mm / 300 DPI 约 840 万点；`^GFA` 按行分段，每段不超过官方规定的 99999 字节。

依赖固定版本 `@napi-rs/canvas`、`jsbarcode`；`@zxing/library` 仅作测试解码。字体来源、固定上游提交、摘要及 SIL OFL 许可证随 `backend/assets/fonts/` 保存；`Dockerfile.backend` 复制资源后运行 `backend/scripts/check-label-renderer.cjs`，缺少 Linux 原生依赖或字体时构建即失败。无数据库迁移或打印客户端协议变更。

参考：[Zebra Graphic Field 指令](https://docs.zebra.com/content/tcm/us/en/printers/software/zpl-pg/zpl-commands/%5Egf.html)、[Noto CJK 官方源码](https://github.com/notofonts/noto-cjk)、[Canvas 官方源码](https://github.com/Brooooooklyn/canvas)。

## 执行与验证计划

1. 补点阵回归，锁定中文与 203/300 DPI 下 PNG/ZPL 逐像素一致。
2. 接入字体、渲染线程、默认模板及受鉴权的只读渲染接口。
3. 编辑器编辑/预览共用点阵图，保存/撤销/未保存保护覆盖 DPI。
4. 跑标签、打印专项与前端检查；补本地页面及独立扫码解码验证，核对 Linux 容器运行依赖。
5. 复核 diff 和文档，报告软件验证与真机验收边界。此任务未授权发布。
