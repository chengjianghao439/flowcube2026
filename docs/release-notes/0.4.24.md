# v0.4.24

## 新功能
- 销售单取消支持「逆向归还」：拣货中/待分拣阶段取消订单时，已经从货架上拣出但还没装箱的货物，系统不再直接后台解锁清空——而是要求仓库逐个容器扫码确认放回原货架位置，全部归位后取消才真正生效。避免了"数据上解锁了、货实际还堆在拣货台"导致库位对不上、货被误当成可用库存的问题。PDA 新增「取消清理」工作台入口，供仓库人员处理待归还任务。

## 修复
- 修复销售退货任务在质检通过、等待上架阶段被取消时，已质检合格的容器未被正确处理，导致这批实收货物永久卡在系统里、既不计入库存也无法再上架的问题
- 修复拣货波次中单个任务被单独取消后，整个波次无法完成拣货收尾的问题
- 退货单价格改由系统按原采购单/销售单强制取值，不再信任提交时传入的价格，避免应收应付金额算错
- 采购收货短装（少收）时新增「结束收货」操作，可主动进入待上架流程，不再卡住采购单的关闭结案
- 调拨在途货物遇到运输丢失等无法正常入库的情况，新增「异常了结」操作处理（仅系统管理员可用）
- 修复两处历史数据库结构漂移，确保迁移脚本目录与实际线上库结构一致

## 说明
- 分拣格释放时机做了调整：从「复核完成」延后到「打包完成」，货物在装箱完成前会一直占用分拣格，避免格子被过早挪作他用
