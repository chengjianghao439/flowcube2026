# v0.9.22

本版是一次「把货和账对牢」的修复版：修掉 6 个会让库存、账款或商品建档**静默出错**的问题（含此前完全无法新建商品），全面收紧了仓库数据权限，并让打印、退货、对账、成本的口径在全系统内保持一致。

## 修复

- **新建商品恢复正常**：此前点「新建商品」必定失败（数据库语句错误），现可正常创建。
- **盘点扫码不再误清零已被拣货锁定的货**：扫不到但已被拣货任务锁定的容器，不再被判成盘亏清零（此前会导致该任务永久卡在待出库）。
- **撤回收货不再让在途调拨的货凭空消失**：调拨在途的容器不会再被撤回收货整只作废（此前源仓已减、目的仓未入，账面直接少货且调拨单永久卡住）。
- **补占库存时不允许更换发货仓库**：避免旧仓预占变孤儿、新仓预占被截断。
- **销售收入的折扣口径与利润表一致**：整单折扣按销售侧同一规则净额化，总账应收不再比子账多出折扣金额。
- **销售退货的成本冲回与出库结转严格对称**：出库时成本未知的，退货时也冲回 0，不再凭商品均价冲出一笔导致两边不等。
- **采购入库结算凭证不再因历史来源缺失把应付写掉**：遇到来源不完整的收货明细会明确报错，而不是生成 0 元凭证并自动冲销账面应付。
- **对账单详情与列表、明细、导出显示同一口径**：不再出现「状态已核销、余额却不是 0」，抬头也不再与自身明细对不上。
- **同一请求键不会被误用到别的单据**：断网重连重试时，不会再把上一张单据的成功结果当成这张单据的结果（此前第二张单据实际并未执行）。
- **具体错误提示不再被通用文案顶掉**：密码错误、来源需修复、超收需确认这类可行动的提示会如实显示，不再一律变成「当前操作无效，请刷新后重试」。

## 改进

- **商品 / 供应商编码**：软删除后可以用同一编码重建；并发新建商品撞号会自动换号，不再报「数据已存在」。
- **退货单状态名统一为「已执行」**：此前同一页面筛选显示「已执行」、表格却显示「已退货」。
- **销售列表与查询弹窗的状态名与其它页面一致**：统一为「草稿 / 拣货中」，不再是「待占库 / 执行中」。
- **承运商管理更安全**：顺丰/德邦的月结账号、默认服务与「取号」开关统一在「快递账号绑定」页维护；只改承运商基本资料不会再悄悄清空月结账号并关闭取号。
- **标签打印失败不再中断收货与装箱**：打印基础设施暂时不可用时业务照常记账，并在打印记录页留下一条可补打的失败记录。
- **打印机启用状态只接受「启用 / 停用」**；PDA 设备停用会立即吊销旧票据。
- **PDA 改绑仓库会同时吊销旧票据**，设备必须重新建会话，避免旧票据仍按旧仓库作业。
- **条码打印查询页不再拖慢整个办公室**：此前固定小批量 + 3 秒轮询会打满全局限流，导致同一出口的所有电脑和 PDA 一起收到「请求过于频繁」。

## 安全与权限

- **仓库数据权限全面收紧**：限仓账号此前可以跨仓读取商品可用量、容器、任务池与统计、打印任务、退货来源单、审批单、对账单导出等，现在一律按授权仓库过滤；清空自己的仓库授权不再等于「不限仓」。
- 承运商「本地演示(mock)」平台在生产环境不可启用（此前会让系统签发假快递单号并推进运单状态）。

## 说明

- 本版包含 7 个数据库迁移，部署时自动执行；迁移会先校验是否存在重复的有效编码，有脏数据会明确中止而不是静默处理。
- 桌面端与 PDA 安装包随本版同步更新，包含上述界面口径与权限修复。
