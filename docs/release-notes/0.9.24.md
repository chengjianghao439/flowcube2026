# v0.9.24

本版是**预防性加固与提速**：修掉一处「角色数量涨上来之后才会炸」的数据库容量限制，并让采购计划与工资单的批量生成明显更快。界面与上一版一致。

## 修复

- **角色数量增长到一定规模后，给新角色配权限或挂用户会失败（提前修复，当前尚未触发）**。角色主表已经是 BIGINT，但「用户所属角色」与「角色权限关联」两张表的角色 ID 列还停留在上限 255 的 TINYINT，两者又没有外键约束——所以问题不会在新建角色时暴露，而是等到**给第 256 个及以后的角色分配权限、或把用户挂到这些角色上**时才报错，错误信息是数据库层的「数值超出范围」，看不出跟角色数量有关。本版把两张表对齐为 BIGINT，已有数据不变，角色数量继续增长不会再撞到这个上限。

## 改进

- **采购计划生成更快**：此前每生成一个商品要单独往返数据库 3 次（查供应、查在途、写快照），现改为批量查询 + 批量写入。生成上百行商品时，数据库往返次数从 300 次以上降到 2 次。
- **工资单创建更快**：此前逐人插入工资明细，现改为一次性批量写入，人数越多差别越明显。

## 加固

- **发布流程的部署锁等待时间三方对齐**：浏览器部署、PDA 构建与桌面构建会竞争服务器上的同一把部署锁，此前的等待上限不一致（有 5 分钟、有 30 分钟），错峰发布时先拿到锁的一方若耗时较长，等待过短的一方会被强杀而失败（线上服务不受影响，但那次部署不会生效）。现统一为 30 分钟。
- **新增两条自动检查**：一条守住项目说明文件不会因体积超限而被静默截断（此前的失败方式是「文件都在、但最权威的说明根本没进模型上下文」，全链路不报错）；一条守住数据库动态查询里的表名、列名必须经过白名单校验。

## 说明

- 桌面端与 PDA 界面、功能与上一版一致，仅随系统同步版本号。
