# 客户与供应商往来明细

## 范围与入口

- 客户管理、供应商管理的行操作新增「往来明细」，仅 PAYMENT_VIEW 可见；独立工作区页面按单位 ID 区分，保留原单查看权限。
- 页面、财务菜单及跳转标题统一为「现结客户账款」「现结供应商账款」「月结客户对账」「月结供应商对账」。原路由、现结/月结筛选不变；财务总览与退货业务中的应收/应付术语仍表示全量。
- 「按单登记」初次打开默认未结清（未付/未收及部分收付款，余额大于零），不限创建日期。高级查询可选已结清或全部；清空不恢复今天日期。API/导出共用 `status=unsettled` 条件，同时修正导出遗漏单号、往来方、确认状态、日期及金额条件的问题。专项：`npm run smoke:payments-default-scope`。
- 明细覆盖全部结算方式，提供记账日期查询、期初、本期增加/减少、期末、每笔余额、原单和收付款详情、CSV 导出。金额最多四位小数，导出避免公式注入。

## 账款事实与历史边界

迁移 238 建立 `party_ledger_meta` 和 `party_ledger_events`：已有账款按 `total_amount-paid_amount` 结转，已有汇款按未核销余额的负数结转。旧系统没有保存全部改价、改单、重算的历史数值，因此不倒推旧流水，也不把结转日期伪装成原出入库日期。页面明确显示完整记账开始时间；查询更早期间给出历史不完整提示。

后续原事务中的触发器记录账款总额变化、直接收付款分录（退款是负分录）以及汇款单金额。带 receipt_id 的核销分录不再次记账。收款 1,200、核销 1,000 后仍保留 200 预收；不因核销重复减少余额。退货/退款事件在同事务补充真实业务单号，不增加第二笔金额。

正余额表示客户欠款或待付供应商款项；负余额表示预收、预付或应退款项。它不是资金账户余额。账款与原有账户、核销规则继续是事实源，新事件用于解释发生过程。只能经现行业务入口改账，禁止绕开入口直接删除或改写历史收付款。

## 单位归属与核销

- 账款从原销售单 customer_id、采购单 supplier_id 固化单位 ID；原档案改名不改变已记流水。
- 迁移 239 为 payment_receipts 增加 party_id。已有核销优先用所核账款的源单 ID；只有未核销汇款才使用现名/原单快照名的唯一完全匹配。名称复用、混合/无法关联的单据不猜归属。
- 新汇款从核销账款推导稳定 ID；纯预收/预付可通过「选择客户/供应商」显式确定 ID，后端复核。旧客户端仅传名称时兼容现名与历史快照名的唯一归属；不清楚的仍留空供核查。
- 继续核销必须属于同一单位 ID，未归属汇款不能核销到已知单位；同为空的历史手工账款仍沿用名称校验。迁移 240 让触发器直接使用服务层验证后的 ID，不能按名称重新猜测空归属。更名后按单位 ID 查询待核销账款/对账单；手工/运费无来源 ID 的历史记录保留财务总列表，不塞进某家单位。
- 财务使用公司级 PAYMENT_VIEW，不盲加仓库过滤；打开原单仍由原业务权限和仓库范围校验。

## 查询一致性

`GET /api/payments/party-ledger?type=1|2&partyId=<id>&startDate=&endDate=&page=&pageSize=`。单次读取为只读 REPEATABLE READ 事务，金额在 MySQL DECIMAL 内聚合；按记账时间、事件 ID 稳定排序，SQL 窗口先计算全部前序余额再取日期范围。

每批最多 500 行，前端批量加载全部结果。首批返回 snapshotId 和 snapshotCount（该单位在上界内的全部事件数量，含期间之前）；续批携带两者。较小 ID 的迟提交若改变期初或明细，返回 409，丢弃残缺批次并重查。此机制是批次一致性校验，不宣称跨 HTTP 请求共享数据库快照。批次固定登录会话且支持取消。

## 迁移与部署

必须先停止业务写入，包括 scheduler/worker，再做历史结转。Docker 发布脚本实际停止 backend 后才执行迁移；迁移开始但未完整成功时保持后端停写，避免部分 DDL 或触发器缺失期间漏账。首次应用 240 后，本次健康/门禁失败也保持停写，禁止恢复不传单位 ID 的旧后端；必须核实完整迁移并使用兼容新后端恢复。停写后尚未核实兼容性同样禁止重启。部署额外检查实际旧镜像 `io.flowcube.party-ledger-contract=1` 标签，覆盖迁移成功但上次门禁失败后的重试；不能只看数据库已有 240 就误启旧代码。核实旧镜像与数据库兼容后才允许正常回退。非 Docker 由原进程管理器停写后显式设置 FLOWCUBE_MIGRATION_WRITES_PAUSED=1；脚本不能猜测并停止未知服务。

MySQL 开启 binlog 时，创建触发器需要迁移权限。本地此次用已配置的开发库管理员完成迁移，`dev:mysql8` 也仅对迁移进程使用管理员；运行服务仍用原普通账号，未改 backend/.env。迁移器在结转前检查创建权限，避免权限失败留半次结转。Docker 发布在停写窗口保存 log_bin_trust_function_creators 原值，临时启用以执行迁移，成功、失败及中断均恢复原值；恢复失败保持停写并报错，不给应用永久 SUPER 权限。迁移文件不包含凭据。

触发器和回填与业务代码一同发布；不能只上传前端。页面烟雾同步检查「月结供应商对账」新标题。迁移结果在开发库和独立测试库中验证，不代表生产已部署。
