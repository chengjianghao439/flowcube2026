# 开单提效第一阶段（2026-09-12）

## 范围与现行行为

在上一轮 `8262fec` 的独立工作树继续实现。用户同意从高频开单提效开始，本阶段不执行真实业务/设备/承运商验收，不包含采购建议深化或经营报表的新决策口径，不推送、不发版。

- 销售新建、草稿编辑、执行/占库期改单以及采购新建/草稿编辑，第一次保存前保持安静；保存时一次列出当前所有填写问题，之后随输入实时更新。点击问题聚焦当前表单控件，隐藏工作区同名字段不被误选。
- 头字段、行数量/单价、销售电话/折扣由 `collectOrderIssues` 集中收集。行提示保留当前显示行号及商品名称，导航依赖稳定行 key。销售空占位行仍忽略；采购必须完整选品、正整数数量且单价可为零。销售数量和单价为正，拒绝 NaN/Infinity。前端检查不替代后端权威校验。
- 在明细数量、单价输入框按 Enter 前进，Shift+Enter 返回；跳过禁用控件，末行聚焦添加商品按钮，不自动添加、不保存。保留原生 Tab，组合输入和其他修饰键不拦截。
- 采购选品后聚焦数量并选中值，销售保留此行为。销售查价期间可手动改价，主动输入优先于此前的异步请求。
- 销售表单状态/操作独立到 `useSaleOrderForm.ts`。查价请求绑定行、商品及客户身份；旧响应、删除行、卸载回调不覆盖当前状态，loading 由最新有效请求管理。明确切换客户时仍重新定价；查询失败、无可用价格或未完成时阻止保存。失败显示原因及“确认当前单价”，用户明确确认或修改后才解除阻止。详细测试见 `order-price-lookup-2026-09-12.md`。
- 电脑 UI 检查发现商品选择弹窗默认 1200px 在 1005px 窗口中遮掉确认按钮。公共 `AppDialog` 对默认/恢复尺寸和窗口变化约束至 95vw/90vh；窗口变化重新居中，临时限制不覆盖保存的偏好。拖拽从实际呈现边界开始，保护剩余视口，商品列继续区域内横向滚动。
- 沿用现有选品、客户价格、权限、单位换算、请求键和保存 API。没有引入历史成交价或自动业务决策。
