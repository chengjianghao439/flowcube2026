## 当前规则

- F06：试算平衡和资产负债表按 SQL 占位符实际顺序传日期和账套。验收必须核对非零金额、期初、本期、期末、未来期间排除及独立账套，不能仅比较借贷相等。
- F07：账号更新、密码重置和删除在同一事务内按用户 ID 顺序锁定实际操作人及目标账号，使用数据库当前角色。非超管不能修改、禁用、降级、重置密码或删除超管。缺少有效操作人/操作人已停用时拒绝；普通管理员管理普通账号与超管自身重置保持可用。密码重置仍增加 `token_version`。
- F08：采购凭证根行保留 `(company_id, source_type, source_id)` 唯一业务锚点。金额变化、归零或来源消失时保留原分录，追加同来源的反向凭证；有新金额时再追加正向版本。迁移 `232_acct_voucher_source_revisions.sql` 新增 `source_root_id`，用于自动反冲及正向修订指向根凭证。恢复来源不会重新激活旧分录；未变来源不会追加凭证。人工红字不设置该关联；最新正向版本被人工冲销后，自动生成永久跳过该来源，不能自动推翻人工决定。
- F08 期间边界：同账套凭证写入与结账共用账套事务行锁；期间尚未建行时也具备稳定锁对象。显式生成已结账期间返回 `ACCT_PERIOD_CLOSED`，全量生成跳过关闭期间并计入 `skippedClosed`。旧版本与新版本涉及的期间都必须开放；先反结账才能修订锁定账面。保护同时落在 `upsertVoucher` 公共入口，覆盖固定资产/工资直接调用者。凭证号 `MAX` 使用 `FOR UPDATE` 当前读，防止调用者在取账套锁前已建立旧快照，导致仍分配出已使用的序列号。
- F09：仅未参与冲销的普通手工凭证可删除。`is_reversal`、`reversed_id`、已冲销状态或反向关联任一存在均拒绝普通删除；自动采购修订沿用采购来源，仍不可普通删除。前端菜单已由客户端修复任务同步。通用/金蝶凭证导出与总账同口径纳入原凭证和红字，不按 `status<>3` 剔除原凭证；反向分录自然抵消，保留追溯记录及正确净额。
- F10：无匹配的商品改价审批流（未配置、停用或金额不匹配）返回 `409 / PRICE_CHANGE_APPROVAL_FLOW_REQUIRED`，提示管理员检查配置，事务回滚且商品价格不变；有适用流程则正常生成待审批实例。

## 部署与剩余限制

新代码需要先执行迁移 232；旧凭证无需回填，既有来源行自然作为根。生产已存在的账面偏差要在已授权的核对后，按开放期间生成流程处理；本任务不擅自反结账或修改生产账款。

公司级业务事实与多账套凭证的原有口径不改变。账套锁会使同账套会计写操作串行执行，优先保证结账/修订/号段一致性；后续若吞吐不足，应在保持期间边界的前提下细分锁，不得移除保护。
