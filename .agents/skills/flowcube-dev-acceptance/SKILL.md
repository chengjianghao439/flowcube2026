# 极序开发与验收协调

本技能只负责规则路由、测试选择和证据分层，不另建业务定义或发布流程。

## 先确定现场

- 核对实际仓库、分支、完整 HEAD、`git worktree list`、`git status --short --branch` 和相关 diff；选定一个工作树，保留既有改动，不凭路径名推断版本或部署状态。
- 先读适用的上级及目录级 [AGENTS.md](../../../AGENTS.md)，再按下表读受影响主题、当前实现、迁移与调用链。表内路径相对本技能文件；文中源码路径相对仓库根目录。
- 当前用户要求优先；主题文档内的日期、历史“未提交/已发布”、旧示例和测试数字须当场核实。发现冲突时列出要求、代码/文档来源和影响，只暂停依赖该争议的改动，其余工作继续；不为过测试擅改业务定义。

## 按影响读取，保持一个事实来源

| 影响 | 先读 | 核对重点 |
|---|---|---|
| 所有开发与验收 | [验证命令](../../../docs/verification-commands.md) | 沿 AGENTS 的执行时机，先审 diff 和测试脚本，再决定现在执行或列为待发版前验证。 |
| UI、列表、大数据 | [前端与 PDA](../../../docs/frontend-pda-conventions.md)、[筛选与返回](../../../docs/workspace-filter-return.md) | 浅色紧凑，不增加深色主题或可见分页；复用有界读取、按需续读和虚拟列表，保留筛选、滚动、查询草稿及详情返回状态，轮询不清输入或抢焦点。已有内部分页、快照刷新和显式重置按原协议处理。 |
| 数量、单位、收货、盘点等全部数量写入 | [全数量与固定单位](../../../docs/sale-shipping-quantity-policy.md)、[业务语义](../../../docs/business-semantics.md) | 商品“允许小数数量”默认关闭，开启仍最多两位；原输入及未取整换算结果先验证，不只限制销售。新销售固定唯一单位，历史单位与换算按原事实及现有边界处理。 |
| 订单、退货、结算与资金 | [实际金额按分](../../../docs/cash-cents-policy.md)、[财务规则](../../../docs/finance-permission-time.md) | 最终订单、实际退货和结算金额按政策四舍五入到两位；单价、成本与中间计算保留必要精度。历史非分事实保留并待核，不静默舍入、改原请求或重写旧账。 |
| 库存、预占、状态机、幂等 | [库存事务](../../../docs/inventory-transaction-invariants.md)、[业务语义](../../../docs/business-semantics.md)、[后端与 SQL](../../../docs/backend-api-sql-conventions.md) | 沿现有事实源、事务连接、锁序、权限和回执模型，不重写库存或预占定义。运费只记录；不顺带计入成本、应付或凭证。 |

| 打印、桌面、PDA | [打印与运维](../../../docs/print-deploy-ops.md)、[本地预览验收](../../../docs/local-preview-acceptance.md) | 分清入队、领取/回执、RAW 提交、设备实际出纸；浏览器中的 PDA 不代表真机扫码或安装。 |
| 发布、更新、部署咨询 | [已有发布技能](../release-flowcube/SKILL.md)、[RELEASE](../../../docs/RELEASE.md)、[DEPLOY](../../../docs/DEPLOY.md) | 复用完整现行门禁及镜像磁盘收尾，既有用户批准规则原样适用。读流程、修代码或做验收计划不自动执行版本脚本、提交、推送或发布。 |

视觉改进按需复用 [impeccable](../impeccable/SKILL.md) 的对应子流程或 [frontend-design](../frontend-design/SKILL.md)。它们提供视觉方法；极序的浅色紧凑、已有组件及用户明确要求优先。不因通用设计建议新增主题、动画、依赖或改造业务流程。impeccable 当前是文字精简移植，不能假定其 CLI、live、hook 或模板脚本可用；使用前仍核实现有能力。

## 选择验证，明确每层能证明什么

1. 按实际 diff 列出受影响业务入口、失败/重试/并发路径与现有测试。核对 `package.json` 及测试调用链后选最小有效检查；沿 AGENTS 的集中验证时机，必要的故障或即时验收先做窄检查。共用函数和路由契约的发版前全量要求仍保留。纯文档/技能改动检查格式、引用和 diff，不起业务服务或数据库。
2. 涉及数量须检查收货、盘点等受影响入口及覆盖守卫；金额须包含半分舍入、分批退货闭合与历史非分负例；库存须包含事务、同键重放及并发守恒。直接从主题文档选命令，不把这里变成另一份命令清单。
3. 任何数据库/API 测试先核隔离实例、回环目标、归属和清理边界，使用合成数据；不连生产库，不把共享开发库当临时库。读取历史记录或发现可用脚本不构成执行授权；当次会话受阻的探针或外部动作不改名、换入口或换环境重跑。
4. 单元/VM/mock/jsdom 只证明受控规则或组件行为；实际 API/独立数据库结果证明对应后台行为。用 API 预置夹具或发请求不算 GUI 点击完成。GUI 证据记录任务代码、服务/账号范围、实际交互及可复核画面，单独说明夹具准备与模拟条件。
5. UI 验收覆盖正常、空、失败/重试、详情返回、轮询、隐藏再激活及大数据边界。记录样本量、已加载/总量、挂载规模和请求/卡顿现象；截断结果不可声称全量，jsdom 几何模拟不可声称设备流畅。未经允许不操作用户界面或业务系统。
6. lint、类型检查、构建、CI、下载哈希、Windows 安装/更新、PDA 真机、实际出纸分别报告；构建通过不能替代真机或纸张验收。设备证据应含版本、设备/打印机及操作结果；缺设备或权限时明确“未验证”，不填推测通过。

## 交付

给出改动文件与目的、实际执行命令及退出结果、证据所在、冲突与待决项。逐项区分已实现、已提交、已推送、已部署和已验证；未执行、受阻、环境失败与产品失败分开。当前代码有已知限制时随结论说明，不把旧报告的绿灯挪作本轮结果。
